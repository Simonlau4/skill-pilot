# 团队分享站：部署与管理

分享站保存团队技能商店的上架信息、技能文件、星级评价和看板上报的商店技能安装记录；安装记录只用来汇总人数，不读取任何人的本机技能库或 Skill Pilot 设置。浏览、上架、安装和评价由各自电脑看板的「团队」页完成，见下文“同事怎么用”。分享站本身没有网页界面。

分享站有两种加入方式：

- **开放加入**：启动时加 `--open`，适合可信局域网里的小团队。启动后把地址告诉同事，同事填自己的名字即可加入，不用管理员发口令。局域网里知道地址的人都能加入并看到整个商店，所以只在可信网络开放。
- **只限成员（默认）**：启动时不加 `--open`，管理员为每位同事生成口令并单独交付。

两种方式都使用成员口令认出每个人；开放加入时由看板自动领取并保存在自己电脑上，不用自己填写。除首次加入外，所有访问都需要成员口令，包括查看商店。每位成员可上架多个技能，同名技能再次上架时替换自己的旧版；带文件的只留最新版。同一个 GitHub 来源或同名飞书官方技能合在一张卡片里，自制或改过的技能按作者分开。每张卡片一人一条评价，可以修改或删除；自己上架的不能评价。管理员在运行分享站的电脑上用命令加、删成员。

## 准备

- 一台一直开着的局域网电脑或 NAS。直接运行支持 Linux、macOS，需要 Python 3.11.4 或更高版本，只用标准库；容器方式使用官方 Python 镜像。
- 获取包含 `hub` 命令的 Skill Pilot 版本并解压。分享站无需安装桌面启动器，也不需要第三方账号或密钥。
- 准备独立的数据文件夹，运行账号必须能够读写它。程序文件夹和数据文件夹分开保存，路径可以含空格。每个数据文件夹只运行一份分享站；请使用本机磁盘上的文件夹，避免跨机器共享同一份数据。
- 电脑或 NAS 的局域网地址最好固定。默认监听所有网卡的 `8765` 端口；只放行可信局域网，关闭路由器端口转发，不向外网开放。端口占用时换一个端口，防火墙和访问地址也要一起改。

下面用 `/srv/Skill Pilot` 表示程序文件夹，`/srv/Team Hub Data` 表示数据文件夹。这两个都是示例位置，请换成自己机器上的位置，并保留引号。

**直接连接时在局域网内明文传输口令、技能文件和评价。** 同一网络内能监听流量的人可能读到它们，口令持有者也能以该成员身份操作。只在可信网络使用；需要加密时，放在 NAS 或系统已有的加密访问入口后面，并禁止绕过该入口直连分享站。分享站自身不申请或管理证书。

## 方式 1：直接运行

先确认 Python 版本，再进入程序文件夹：

```bash
python3 --version
cd "/srv/Skill Pilot"
```

下面的启动示例采用开放加入，不用提前添加成员。只限成员时，先为同事添加成员（显示名可以重复，成员编号各不相同；名字为 1–40 字，不能换行或含控制字符）：

```bash
python3 -m skill_pilot hub add-member "Acme 示例成员一" --data "/srv/Team Hub Data"
python3 -m skill_pilot hub add-member "Acme 示例成员二" --data "/srv/Team Hub Data"
python3 -m skill_pilot hub members --data "/srv/Team Hub Data"
```

添加成功后显示成员编号和口令，**口令只显示这一次**，不会写入数据文件。请通过各自的私信或公司认可的密码交付方式，把分享站地址（例如 `http://<局域网地址>:8765`）和对应口令单独交给同事，不发到公开群或项目文件里。成员编号用于日后删除，查看成员命令不会显示口令。

在程序文件夹中，用下面这条固定命令启动；手动重启时仍用同一条命令：

```bash
/usr/bin/env python3 -m skill_pilot hub serve --data "/srv/Team Hub Data" --host 0.0.0.0 --port 8765 --open
```

看到“分享站已启动”即可使用，提示里会写明是否开放加入。只限成员时去掉命令末尾的 `--open`。终端需要保持打开；临时试用结束按 Ctrl+C 停止。只想在该机器上检查时可用 `--host 127.0.0.1`，同事将不能直接连接。省略 `--host` 和 `--port` 时分别采用 `0.0.0.0`、`8765`。所有命令都必须明确填写 `--data`，不会默认使用主目录。

### 电脑或 NAS 重启后自动运行

将上面的固定启动命令加入系统自带的开机任务，指定程序文件夹为工作目录、用有权读写数据文件夹的普通账号运行，并设置异常退出后重试。macOS 可使用系统的 launchd；不同 NAS 使用各自的任务管理入口。

常见 Linux 使用 systemd。先运行 `command -v python3`，确认开机任务能够找到同一个合适版本；若系统服务找不到它，将下方 `/usr/bin/env python3` 换成查到的 Python 程序完整位置。创建 `/etc/systemd/system/skill-pilot-team.service`，将 `<运行账号>` 替换为现有的普通系统账号，并按实际位置修改两个文件夹：

```ini
[Unit]
Description=Skill Pilot Team Hub
After=network.target

[Service]
Type=simple
User=<运行账号>
WorkingDirectory=/srv/Skill Pilot
ExecStart=/usr/bin/env python3 -m skill_pilot hub serve --data "/srv/Team Hub Data" --host 0.0.0.0 --port 8765 --open
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

保存后启用并查看运行结果。已手动启动的那一份须先按 Ctrl+C 停止，避免占用同一个端口：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now skill-pilot-team
sudo systemctl status skill-pilot-team
```

`enable` 负责开机运行，`Restart=always` 负责运行中退出后重试。之后可用 `sudo systemctl restart skill-pilot-team` 重启、`sudo systemctl stop skill-pilot-team` 停止。开机任务仍指向相同的数据文件夹，成员、原口令和分享都会保留。请在部署机器重启一次，确认服务自动运行，再让同事连接；不同系统的开机配置需在各自机器验收。

## 方式 2：NAS 容器功能

需要 NAS 或电脑已有可用的容器环境。直接使用官方 `python:3.12-slim`，不制作自己的镜像。先创建数据文件夹，再挂载程序和数据两个文件夹：

```bash
mkdir -p "/srv/Team Hub Data"
docker run -d --name skill-pilot-team \
  --restart unless-stopped \
  -p 8765:8765 \
  -v "/srv/Skill Pilot:/app:ro" \
  -v "/srv/Team Hub Data:/data" \
  -w /app -e PYTHONDONTWRITEBYTECODE=1 \
  python:3.12-slim \
  python3 -m skill_pilot hub serve --data /data --host 0.0.0.0 --port 8765 --open
```

也可在 NAS 的容器管理界面填写同样的镜像、挂载、工作目录、端口和命令。程序挂载只读，数据挂载可读写；数据不能只留在容器内部。若改变对外端口，只改 `-p` 左边的数字，同事也使用新的端口。

**启用容器的“自动重启”，并让容器服务随系统开机运行。** 上面的 `--restart unless-stopped` 会在容器异常退出或容器服务重新启动后恢复运行。手动停止的容器会保持停止，需用 `docker start skill-pilot-team` 重新启用。

成员管理同样在这台机器上进行，使用容器内的数据位置：

```bash
docker exec skill-pilot-team python3 -m skill_pilot hub add-member "Acme 示例成员一" --data /data
docker exec skill-pilot-team python3 -m skill_pilot hub members --data /data
docker exec skill-pilot-team python3 -m skill_pilot hub remove-member <成员编号> --data /data
```

通过 `docker logs skill-pilot-team` 查看启动结果。部署后执行 `docker restart skill-pilot-team`，确认原成员口令仍能访问、原分享仍能读取，再重启 NAS 验证开机恢复。只要保留数据挂载文件夹，重启或重新创建容器都保留成员和分享。

关闭开放加入时，去掉启动命令中的 `--open` 并重启分享站。已经加入的成员及其口令继续有效，只是不再允许新成员凭名字加入；要停用某位成员，仍需执行删除成员命令。

## 删成员、备份与更新

直接运行时，在程序文件夹执行：

```bash
python3 -m skill_pilot hub members --data "/srv/Team Hub Data"
python3 -m skill_pilot hub remove-member <成员编号> --data "/srv/Team Hub Data"
```

删除后，这位成员的口令立即失效，上架信息、技能包、技能文件、他写的评价和装了哪些技能的记录一并删除，不再计入安装人数；其他成员的上架不受影响。口令遗失时不能找回原口令，请删除该成员后重新添加，交付新口令，并让同事重新上架。

数据文件夹包含：

| 文件 | 内容 |
| --- | --- |
| `members.json` | 成员编号、显示名、口令的 SHA-256 摘要、创建时间；没有口令原文 |
| `listings/<成员编号>.json` | 此成员上架的全部技能、来源、推荐语和更新时间 |
| `packs/<成员编号>.json` | 此成员整理的技能包，每包保存标题、可选推荐语、技能名单和更新时间 |
| `packages/<成员编号>/<技能名>.json` | 带文件上架的技能包，只保存最新一版 |
| `ratings.json` | 每张技能卡片的成员评分、评价和更新时间 |
| `installs.json` | 每位成员本机已有的商店卡片编号，格式为 `{"installs":{"成员编号":["卡片编号",...]}}`；文件不存在时按空记录处理，只用来算人数 |
| `.lock` | 防止成员管理和同时上传相互覆盖的运行锁；不是账号数据 |

备份时先停止分享站，复制**整个数据文件夹**到受保护的备份位置，再启动。系统服务用 `systemctl stop/start`，容器用 `docker stop/start`，手动运行用 Ctrl+C 和上面的固定命令。备份包含团队技能文件、成员评价和安装记录，应只让管理员访问。恢复时同样先停止，再还原整个文件夹并确认运行账号有读写权限，成员、上架、文件、评价和安装记录要一起备份、一起恢复，不要拼接不同时间的数据。

更新程序时先停止分享站、备份数据，获取包含分享站的新版本并替换程序文件夹内容，保留数据文件夹，之后用原启动命令或开机服务启动。容器方式更新宿主机程序文件夹后重启容器；要更新 Python 镜像时，先拉取官方镜像，再用相同挂载和启动参数重新创建容器。都不需要重新发口令。检查原口令、商店目录、技能文件和评价可用后再结束维护。

从第一期升级时，**分享站和每位同事的看板都要换成支持商店的新版**。接口版本为 2，版本不匹配时看板会说明原因。原 `members.json` 和成员口令继续可用；旧的 `shares/` 名单不读取、不迁移，备份后可以删除。请同事在新版「团队」页重新选择技能上架。

## 同事怎么用

每位同事使用自己电脑上的新版 Skill Pilot 看板。管理员运行一份分享站，同事无需各自再部署。

在「设置 → 团队分享」填写分享站地址和自己的名字，保存并连接后，从页头进入「团队」页。分享站未开放加入时，展开「管理员给了口令？」填写管理员给的口令。已经连过的电脑会先用已存口令，连接成功不会多出一个自己；只有旧身份被拒绝且填写了名字时才会重新加入。明确填写口令时优先使用该口令，填错不会另建成员。这里是查看团队商店、选择本机技能上架、安装和评价的统一入口。上架前会列出疑似含密钥而被拦下的文件；带文件的技能可检查新版，并沿用技能页的更新和撤销流程。飞书官方技能仍通过官方方式安装。

在技能详情里点一次“装上”就加入安装队列，所需技能一起装上；等待时可以关掉详情、继续浏览并添加其他技能。队列会显示等待、正在安装、装好或没装上的原因；失败后可以重试，装好后可到「设置 → 操作记录」撤销。装好的技能默认不给任何 agent 启用，到「技能」页再选择给谁用。

成套技能可以整理为技能包，默认一起安装，也可以取消个别；前置依赖仍须一起装，装好后本机已有的同包技能会加上包名标签。只整理技能包不会改变技能的上架时间。分享站版本较旧时仍可照常浏览、上架和逐个安装技能，更新分享站后才支持技能包，接口版本仍为 2。

打开团队页时，看板会向分享站上报本机状态为“已装”或“有新版”且没有在清理页撤下的商店技能，整份替换本人上次的记录。人数按成员计算，重装和更新不会重复增加，撤下或撤销安装后再读商店会减少；不含上架这张卡片的人，同事只看到人数、看不到是谁装了。只读预览不上报；上报失败仍可浏览，下次读取时重试。旧版分享站不显示人数，其他功能照常；旧版看板连接新版分享站也照常使用，接口版本仍为 2。

上架网上技能时会尽量连同文件一起上传，其他人安装时优先从分享站下载，不必再连 GitHub；早期只上架了来源、没有文件的记录仍从原来源下载。作者在详情里点“上架新版”可补传文件。上传文件受相同的大小、数量和敏感内容限制，无法上传时仍保留原来源供安装。

分享站连不上、口令不对或版本不匹配时，看板会写明原因，自己电脑上的技能不受影响。只读模式下可以浏览和预览，不能上架、下架、装上或评价。

## 接口与连通检查

只有准确的 `POST /api/join` 不需要口令，未开放时返回 `403`。其他接口都带 `Authorization: Bearer <口令>`，没有口令或口令错误返回 `401`；加入地址带查询参数或换了方法，也要先通过口令检查。错误统一返回 `{"error":"中文说明"}`。成功返回 `200`，未知地址返回 `404`，不支持的操作返回 `405`。

| 操作 | 结果 |
| --- | --- |
| `POST /api/join` | 请求体 `{"name":"显示名"}`；开放时返回 `{"service":"skill-pilot-team","api":2,"member":{"id":"成员编号","name":"显示名"},"token":"口令"}`；未开放返回 `403`，不创建成员 |
| `GET /api/me` | `{"service":"skill-pilot-team","api":2,"member":{"id":"成员编号","name":"显示名"}}` |
| `GET /api/catalog` | `{"cards":[{"key":"卡片编号","listings":[...],"ratings":[...],"installs":0}],"my_installs":[...],"packs":[...]}`；`installs` 为仍在成员名单中、上报装有此卡片且没有上架此卡片的人数（非负整数），`my_installs` 只含请求者本人记录中仍在目录里的卡片编号并排序；卡片和技能包各按更新时间从新到旧，不含文件内容或其他成员的安装记录 |
| `PUT /api/installs/me` | `{"keys":["卡片编号",...]}`；必须是文字列表，去重后只保留当前目录中存在且不是本人上架的卡片，整份替换本人记录，空列表删除本人条目；返回 `{"keys":[保留的编号，排序]}`，不存在或已下架的编号静默丢弃 |
| `PUT /api/listings/me` | `{"listings":[...],"packs":[...]}`；整批上架或替换本人的同名技能，可选的 `packs` 整体替换本人的技能包，和上架在同一次保存中生效；不带 `packs` 保留原包。返回每项的名称、卡片编号、时间及文件版本 |
| `PUT /api/packs/me` | `{"packs":[{"id":"acme","title":"Acme 技能包","skills":["acme-one","acme-two"]}]}`；整体替换本人的技能包，空列表全部拆开，不改卡片上架时间；返回 `{"packs":[...]}`，每包含 `key`、`id`、`member`、`title`、可选 `note`、`skills`、按相同顺序生成的 `cards` 和 `updated_at`；编号为 `pack:<成员编号>:<包编号>`，未变的包保留原时间 |
| `DELETE /api/listings/me/<技能名>` | 下架本人的技能并删除对应文件，同时移出技能包，包少于两个技能时自动拆开；未上架返回 `404`，本人其他上架仍需要它返回 `409` |
| `GET /api/packages/<成员编号>/<技能名>?version=<版本>` | 读取指定上架的最新文件；无文件或已下架返回 `404`，已换成其他版本返回 `409`；也可省略版本参数 |
| `PUT /api/ratings` | `{"key":"卡片编号","stars":5,"text":"示例评价"}`；一人一条，可再次上传替换 |
| `DELETE /api/ratings` | `{"key":"卡片编号"}`；删除自己的评价，没有评价返回 `404` |

第一期的 `/api/shares*` 接口一律返回 `404`。

上传直接发送 JSON 并带上 `Content-Length`，不接受分块上传。一次上架请求最多 **20,971,520 字节（20 MB）**；单个技能最多 **300 个文件、解码后合计 5,242,880 字节（5 MB）**，根目录须有 `SKILL.md`。文件位置只能在技能文件夹内，内容采用标准 base64 编码。评价请求最多 **65,536 字节（64 KB）**，评分须为 1–5 的整数，评价和推荐语最多 200 字、不含换行或看不见的字符。请求超限直接返回 `413`，格式不对返回 `400`。所需技能必须在同一批上架，或已经由本人上架；整批校验通过才保存。

安装记录上报单独限制为 **65,536 字节（64 KB）**，同样带上 `Content-Length`、不接受分块发送。超限返回 `413` 并提示“上报内容超过 64 KB”，`keys` 不是文字列表返回 `400`。保存与成员管理、上架操作使用同一把锁，删除成员时也在同一次保存中删除其安装记录。

单独整理技能包的请求上限为 **65,536 字节（64 KB）**。每位成员最多 50 个包，每包 2–50 个不重复的本人上架技能，同一个技能最多在一个包里，飞书官方技能不能入包。包编号以字母或数字开头，最多 64 个字符，可含字母、数字、点、横线和下划线；包名按用户标签规则整理为 1–20 字，推荐语最多 200 字。未知字段丢弃，校验失败整份不保存。

上架只保留技能名称、中文名、一句话说明、分组、原说明、推荐语、所需技能和受支持的来源字段；文件只保留位置、内容和执行权限。版本、文件数和总大小由分享站计算。多余字段丢掉，不保存本机分配关系或账号设置。

加入请求也须带上 `Content-Length`，最多 **4096 字节**，不接受分块发送。缺少长度返回 `411`，超限返回 `413`，格式或名字不合要求返回 `400`。名字去掉首尾空白后为 1–40 字，不能换行或含控制字符，允许与其他成员同名。加入返回的口令只保存在本人电脑上，不在看板接口、日志或操作记录中显示。

开放的分享站可以先用下面的方式自助加入。返回内容含口令，用只有自己能读的临时文件接收，再读进变量，避免把它打印到终端或公共日志：

```bash
HUB_ADDRESS="http://<局域网地址>:8765"
HUB_JOIN_FILE="$(mktemp)"
curl --fail-with-body --silent --show-error -H 'Content-Type: application/json' \
  --data '{"name":"Acme 示例成员"}' --output "$HUB_JOIN_FILE" "$HUB_ADDRESS/api/join"
HUB_TOKEN="$(python3 -c 'import json, sys; print(json.load(open(sys.argv[1]))["token"])' "$HUB_JOIN_FILE")"
rm -f "$HUB_JOIN_FILE"
curl --fail-with-body -H "Authorization: Bearer $HUB_TOKEN" "$HUB_ADDRESS/api/me"
unset HUB_TOKEN HUB_JOIN_FILE
```

管理员可在终端交互输入口令检查接口；以下示例使用 bash，`HUB_ADDRESS` 换成自己的局域网地址：

```bash
HUB_ADDRESS="http://<局域网地址>:8765"
read -r -s -p '成员口令：' HUB_TOKEN
curl --fail-with-body -H "Authorization: Bearer $HUB_TOKEN" "$HUB_ADDRESS/api/me"
curl --fail-with-body -H "Authorization: Bearer $HUB_TOKEN" "$HUB_ADDRESS/api/catalog"
unset HUB_TOKEN
```

分享站只验证、保存技能信息和文件，不下载来源、不解开技能包、不安装或执行任何上传的文件。服务日志不记录口令、加入的名字、访问路径、评价或文件内容；请勿把添加成员时显示或自助加入时领到的口令保存到公共日志，也不要在打印命令参数的调试模式中运行上述检查。
