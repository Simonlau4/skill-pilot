# 团队分享站：部署与管理

分享站保存团队技能商店的上架信息、技能文件、星级评价和看板上报的商店技能安装记录；安装记录只用来汇总人数，不读取任何人的本机技能库或 Skill Pilot 设置。浏览、上架、安装和评价由各自电脑看板的「团队」页完成，见下文“同事怎么用”。分享站本身没有网页界面。

分享站每天访问一次 GitHub 公开接口，查询最近热门的技能仓库，不需要账号或密钥；查不到时保留上一份，不影响其他功能。

最近热门的每个仓库还会记下三项文件位置，通过 `/api/catalog` 原样提供，接口版本仍为 2：

- `branch`：默认分支。限 1–100 个英文字母、数字、点、下划线、横线或斜线，不能含 `..`，不能以斜线开头或结尾。
- `readme_path`：根目录的说明文件，不分大小写，依次优先 `README.md`、`README.markdown`、`README.rst`、`README.txt`、`README`；没有时为 `null`。
- `skill_paths`：所有末段为 `SKILL.md` 的文件位置，排序后最多 30 个。路径最多 300 字，每段不能为空、不能是 `.` 或 `..`，不能含控制字符或反斜线。

文件清单被截断或超过读取上限时，后两项分别为 `null` 和空列表，不根据残缺清单猜位置。旧数据缺少这三项仍然有效；旧看板忽略新增字段，新看板连接旧分享站时照常浏览，但不自动整理中文介绍。

原文由各自电脑直接从 `raw.githubusercontent.com` 下载。填好 AI 服务后，打开团队页会在本机后台逐个整理；原文和中文结果保存在本机，分享站不调用 AI，也不在同事之间共享结果。升级分享站并重启后，下一次成功刷新最近热门时才会补齐新字段。

分享站有两种加入方式：

- **开放加入**：启动时加 `--open`，适合可信局域网里的小团队。启动后把地址告诉同事，同事填自己的名字即可加入，不用管理员发口令。局域网里知道地址的人都能加入并看到整个商店，所以只在可信网络开放。
- **只限成员（默认）**：启动时不加 `--open`，管理员为每位同事生成口令并单独交付。

两种方式都使用成员口令认出每个人；开放加入时由看板自动领取并保存在自己电脑上，不用自己填写。除首次加入外，所有访问都需要成员口令，包括查看商店。每位成员可上架多个技能，同名技能再次上架时替换自己的旧版；带文件的只留最新版。同一个 GitHub 来源或同名飞书官方技能合在一张卡片里，自制或改过的技能按作者分开。每张卡片一人一条评价，可以修改或删除；自己上架的不能评价。管理员在运行分享站的电脑上用命令加、删成员。

## 准备

- 一台一直开着的局域网电脑或 NAS。直接运行支持 Linux、macOS，需要 Python 3.11.4 或更高版本，只用标准库；容器方式使用官方 Python 镜像。
- 获取包含 `hub` 命令的 Skill Pilot 版本并解压。分享站无需安装桌面启动器；可选的飞书反馈需要管理员自己的多维表格自动化接收地址。
- 准备独立的数据文件夹，运行账号必须能够读写它。程序文件夹和数据文件夹分开保存，路径可以含空格。每个数据文件夹只运行一份分享站；请使用本机磁盘上的文件夹，避免跨机器共享同一份数据。
- 电脑或 NAS 的局域网地址最好固定。默认监听所有网卡的 `8765` 端口；只放行可信局域网，关闭路由器端口转发，不向外网开放。端口占用时换一个端口，防火墙和访问地址也要一起改。

下面用 `/srv/Skill Pilot` 表示程序文件夹，`/srv/Team Hub Data` 表示数据文件夹。这两个都是示例位置，请换成自己机器上的位置，并保留引号。

**直接连接时在局域网内明文传输口令、技能文件和评价。** 同一网络内能监听流量的人可能读到它们，口令持有者也能以该成员身份操作。只在可信网络使用；需要加密时，放在 NAS 或系统已有的加密访问入口后面，并禁止绕过该入口直连分享站。分享站自身不申请或管理证书。

## 方式 1：直接运行

先确认 Python 版本，再进入程序文件夹：

```bash
python3 --version
cd "/srv/Skill Pilot"
```

下面的启动示例采用开放加入，不用提前添加成员。只限成员时，先为同事添加成员（显示名可以重复，成员编号各不相同；名字为 1–40 字，不能换行或含控制字符）：

```bash
python3 -m skill_pilot hub add-member "Acme 示例成员一" --data "/srv/Team Hub Data"
python3 -m skill_pilot hub add-member "Acme 示例成员二" --data "/srv/Team Hub Data"
python3 -m skill_pilot hub members --data "/srv/Team Hub Data"
```

添加成功后显示成员编号和口令，**口令只显示这一次**，不会写入数据文件。请通过各自的私信或公司认可的密码交付方式，把分享站地址（例如 `http://<局域网地址>:8765`）和对应口令单独交给同事，不发到公开群或项目文件里。成员编号用于日后删除，查看成员命令不会显示口令。

在程序文件夹中，用下面这条固定命令启动；手动重启时仍用同一条命令：

```bash
/usr/bin/env python3 -m skill_pilot hub serve --data "/srv/Team Hub Data" --host 0.0.0.0 --port 8765 --open
```

看到“分享站已启动”即可使用，提示里会写明是否开放加入。只限成员时去掉命令末尾的 `--open`。终端需要保持打开；临时试用结束按 Ctrl+C 停止。只想在该机器上检查时可用 `--host 127.0.0.1`，同事将不能直接连接。省略 `--host` 和 `--port` 时分别采用 `0.0.0.0`、`8765`。所有命令都必须明确填写 `--data`，不会默认使用主目录。

### 电脑或 NAS 重启后自动运行

将上面的固定启动命令加入系统自带的开机任务，指定程序文件夹为工作目录、用有权读写数据文件夹的普通账号运行，并设置异常退出后重试。macOS 可使用系统的 launchd；不同 NAS 使用各自的任务管理入口。

常见 Linux 使用 systemd。先运行 `command -v python3`，确认开机任务能够找到同一个合适版本；若系统服务找不到它，将下方 `/usr/bin/env python3` 换成查到的 Python 程序完整位置。创建 `/etc/systemd/system/skill-pilot-team.service`，将 `<运行账号>` 替换为现有的普通系统账号，并按实际位置修改两个文件夹：

```ini
[Unit]
Description=Skill Pilot Team Hub
After=network.target

[Service]
Type=simple
User=<运行账号>
WorkingDirectory=/srv/Skill Pilot
ExecStart=/usr/bin/env python3 -m skill_pilot hub serve --data "/srv/Team Hub Data" --host 0.0.0.0 --port 8765 --open
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

保存后启用并查看运行结果。已手动启动的那一份须先按 Ctrl+C 停止，避免占用同一个端口：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now skill-pilot-team
sudo systemctl status skill-pilot-team
```

`enable` 负责开机运行，`Restart=always` 负责运行中退出后重试。之后可用 `sudo systemctl restart skill-pilot-team` 重启、`sudo systemctl stop skill-pilot-team` 停止。开机任务仍指向相同的数据文件夹，成员、原口令和分享都会保留。请在部署机器重启一次，确认服务自动运行，再让同事连接；不同系统的开机配置需在各自机器验收。

## 方式 2：NAS 容器功能

需要 NAS 或电脑已有可用的容器环境。直接使用官方 `python:3.12-slim`，不制作自己的镜像。先创建数据文件夹，再挂载程序和数据两个文件夹：

```bash
mkdir -p "/srv/Team Hub Data"
docker run -d --name skill-pilot-team \
  --restart unless-stopped \
  -p 8765:8765 \
  -v "/srv/Skill Pilot:/app:ro" \
  -v "/srv/Team Hub Data:/data" \
  -w /app -e PYTHONDONTWRITEBYTECODE=1 \
  python:3.12-slim \
  python3 -m skill_pilot hub serve --data /data --host 0.0.0.0 --port 8765 --open
```

也可在 NAS 的容器管理界面填写同样的镜像、挂载、工作目录、端口和命令。程序挂载只读，数据挂载可读写；数据不能只留在容器内部。若改变对外端口，只改 `-p` 左边的数字，同事也使用新的端口。

**启用容器的“自动重启”，并让容器服务随系统开机运行。** 上面的 `--restart unless-stopped` 会在容器异常退出或容器服务重新启动后恢复运行。手动停止的容器会保持停止，需用 `docker start skill-pilot-team` 重新启用。

成员管理同样在这台机器上进行，使用容器内的数据位置：

```bash
docker exec skill-pilot-team python3 -m skill_pilot hub add-member "Acme 示例成员一" --data /data
docker exec skill-pilot-team python3 -m skill_pilot hub members --data /data
docker exec skill-pilot-team python3 -m skill_pilot hub remove-member <成员编号> --data /data
```

通过 `docker logs skill-pilot-team` 查看启动结果。部署后执行 `docker restart skill-pilot-team`，确认原成员口令仍能访问、原分享仍能读取，再重启 NAS 验证开机恢复。只要保留数据挂载文件夹，重启或重新创建容器都保留成员和分享。

关闭开放加入时，去掉启动命令中的 `--open` 并重启分享站。已经加入的成员及其口令继续有效，只是不再允许新成员凭名字加入；要停用某位成员，仍需执行删除成员命令。

## 删成员、备份与更新

直接运行时，在程序文件夹执行：

```bash
python3 -m skill_pilot hub members --data "/srv/Team Hub Data"
python3 -m skill_pilot hub remove-member <成员编号> --data "/srv/Team Hub Data"
```

删除后，这位成员的口令立即失效，上架信息、技能包、技能文件、他写的评价和装了哪些技能的记录一并删除，不再计入安装人数；其他成员的上架不受影响。口令遗失时不能找回原口令，请删除该成员后重新添加，交付新口令，并让同事重新上架。

数据文件夹包含：

| 文件 | 内容 |
| --- | --- |
| `members.json` | 成员编号、显示名、口令的 SHA-256 摘要、创建时间；没有口令原文 |
| `listings/<成员编号>.json` | 此成员上架的全部技能、来源、推荐语和更新时间 |
| `packs/<成员编号>.json` | 此成员整理的技能包，每包保存标题、可选推荐语、技能名单和更新时间 |
| `packages/<成员编号>/<技能名>.json` | 带文件上架的技能包，只保存最新一版 |
| `ratings.json` | 每张技能卡片的成员评分、评价和更新时间 |
| `installs.json` | 每位成员本机已有的商店卡片编号，格式为 `{"installs":{"成员编号":["卡片编号",...]},"with_mine":["成员编号",...]}`；文件不存在时按空记录处理，只用来算人数 |
| `deliverables/<成员编号>/items/<成品编号>.json` | 此成员上架的成品：名字、版本、一句话说明、用到的技能、复刻配方、文件清单（相对位置 → 内容编号和大小）和更新时间 |
| `deliverables/<成员编号>/blobs/<内容编号>` | 同一位成员的技能和成品文件按 SHA-256 存一份；下架或换版后清理不再使用的内容 |
| `feedback.json` | 署名反馈留底，最多保留最近 200 条且总大小不超过 1 MB；含成员编号、署名、转发状态及附件清单 |
| `feedback-attachments/<内容编号>.<后缀>` | 随反馈提交的截图留底（PNG、JPEG、WebP），按 SHA-256 存一份；总占用上限 50 MB，超出时按最早记录依次清理截图文件并保留文字留底 |
| `.lock` | 防止成员管理和同时上传相互覆盖的运行锁；不是账号数据 |

备份时先停止分享站，复制**整个数据文件夹**到受保护的备份位置，再启动。系统服务用 `systemctl stop/start`，容器用 `docker stop/start`，手动运行用 Ctrl+C 和上面的固定命令。备份包含团队技能文件、成员评价和安装记录，应只让管理员访问。恢复时同样先停止，再还原整个文件夹并确认运行账号有读写权限，成员、上架、文件、评价和安装记录要一起备份、一起恢复，不要拼接不同时间的数据。

更新程序时先停止分享站、备份数据，获取包含分享站的新版本并替换程序文件夹内容，保留数据文件夹，之后用原启动命令或开机服务启动。容器方式更新宿主机程序文件夹后重启容器；要更新 Python 镜像时，先拉取官方镜像，再用相同挂载和启动参数重新创建容器。都不需要重新发口令。检查原口令、商店目录、技能文件和评价可用后再结束维护。

从第一期升级时，**分享站和每位同事的看板都要换成支持商店的新版**。接口版本为 2，版本不匹配时看板会说明原因。原 `members.json` 和成员口令继续可用；旧的 `shares/` 名单不读取、不迁移，备份后可以删除。请同事在新版「团队」页重新选择技能上架。

## 同事怎么用

每位同事使用自己电脑上的新版 Skill Pilot 看板。管理员运行一份分享站，同事无需各自再部署。

在「设置 → 团队分享」填写分享站地址和自己的名字，保存并连接后，从页头进入「团队」页。分享站未开放加入时，展开「管理员给了口令？」填写管理员给的口令。已经连过的电脑会先用已存口令，连接成功不会多出一个自己；只有旧身份被拒绝且填写了名字时才会重新加入。明确填写口令时优先使用该口令，填错不会另建成员。这里是查看团队商店、选择本机技能上架、安装和评价的统一入口。上架前会列出疑似含密钥而被拦下的文件；带文件的技能可检查新版，并沿用技能页的更新和撤销流程。飞书官方技能仍通过官方方式安装。

在技能详情里点一次“装上”就加入安装队列，所需技能一起装上；等待时可以关掉详情、继续浏览并添加其他技能。队列会显示等待、正在安装、装好或没装上的原因；失败后可以重试，装好后可到「设置 → 操作记录」撤销。装好的技能默认不给任何 agent 启用，到「技能」页再选择给谁用。

连接好以后，也可以在对话里让 agent 用命令完成：`skill-pilot team list` 查看商店；`skill-pilot team publish <技能...>` 上架本机在用的技能，可加 `--note 技能=推荐语`；`skill-pilot team unpublish <技能...>` 下架；`skill-pilot team install <技能名或中文名> --agent <编号>` 装上并分配，有重名时加 `--author <上架人>`。这些命令不带 `--yes` 只预览：上架预览列出要上传的文件、被拦下的疑似密钥文件、一起上架的所需技能和建议的技能包（不要时加 `--skip-pack <编号>`；想自己指定时加 `--pack <包名>`，这次列出的技能会组成这个包，包名已有时加进去）；带 `--yes` 才执行，上架和下架后会再读一次分享站确认。

成套技能可以整理为技能包，默认一起安装，也可以取消个别；前置依赖仍须一起装，装好后本机已有的同包技能会加上包名标签。只整理技能包不会改变技能的上架时间。分享站版本较旧时仍可照常浏览、上架和逐个安装技能，更新分享站后才支持技能包，接口版本仍为 2。

打开团队页时，看板会向分享站上报本机已有且没有在清理页撤下的商店技能（包含本人上架的、状态为“已装”或“有新版”的、“本机有同名技能”及“由外部工具维护”的技能，仅排除明确来自另一个不同公开仓库的同名技能），整份替换本人上次的记录。人数按成员计算，重装和更新不会重复增加，撤下、删除或撤销安装后再读商店会减少；已经上架卡片的成员默认计入，升级看板后按本机实际情况同步；同事只看到人数、看不到是谁装了。只读预览不上报；上报失败仍可浏览，下次读取时重试。旧版分享站不显示人数（或暂不接收本人上架计数），其他功能照常；旧版看板可以继续浏览和安装旧格式的技能，接口版本仍为 2。

上架网上技能时会尽量连同文件一起上传，其他人安装时优先从分享站下载，不必再连 GitHub；早期只上架了来源、没有文件的记录仍从原来源下载。作者在详情里点“上架新版”可补传文件。上传文件受相同的大小、数量和敏感内容限制，无法上传时仍保留原来源供安装。

单个技能最多 **1,000 个文件、合计 100 MB、单文件 50 MB**。文件较多、较大或整批上架超过原先的单次上传大小时，分享站会按文件核对已有内容，只补传缺少的文件。断线后可以重新上架，已传好的文件会复用，已有上架在整批核对通过后才会换成新版。同事在看板里照常点「装上」或更新，下载时会核对每个文件的大小和内容。

大技能需要管理员更新并重启分享站，上架和安装的同事也需要更新看板。原有上架及口令继续使用。旧看板仍显示原格式的技能，更新后即可看到逐文件上架的技能。分享站前面有反向代理时，请允许文件上传请求达到 50 MB。

「我的上架」顶部的「一键更新」会重新核对本机在用的已上架技能，把有本地新版的加入后台队列，不受当前搜索和分组筛选影响。原推荐语和技能包保留；每个技能上传后核对分享站版本，单项失败仍继续后续技能。后台任务显示进度、成功和失败数量及逐项原因，可「重试未完成项」。疑似敏感文件、无法完整读取的文件或尚未上架的新前置依赖需要单独点「上架新版」核对。大技能走同样的逐文件上传流程。

分享站连不上、口令不对或版本不匹配时，看板会写明原因，自己电脑上的技能不受影响。只读模式下可以浏览和预览，不能上架、下架、装上或评价。

## 接口与连通检查

只有准确的 `POST /api/join` 不需要口令，未开放时返回 `403`。其他接口都带 `Authorization: Bearer <口令>`，没有口令或口令错误返回 `401`；加入地址带查询参数或换了方法，也要先通过口令检查。错误统一返回 `{"error":"中文说明"}`。成功返回 `200`，未知地址返回 `404`，不支持的操作返回 `405`。

| 操作 | 结果 |
| --- | --- |
| `POST /api/join` | 请求体 `{"name":"显示名"}`；开放时返回 `{"service":"skill-pilot-team","api":2,"member":{"id":"成员编号","name":"显示名"},"token":"口令"}`；未开放返回 `403`，不创建成员 |
| `GET /api/me` | `{"service":"skill-pilot-team","api":2,"member":{"id":"成员编号","name":"显示名"}}`；新版另返回 `"feedback_supported":true`、`"feedback_configured"`（布尔）、`"feedback_attachments_supported":true`、`"skill_file_upload":true` |
| `GET /api/catalog` | `{"cards":[{"key":"卡片编号","listings":[...],"ratings":[...],"installs":0}],"my_installs":[...],"my_all_installs":[...],"packs":[...]}`；`installs` 为仍在成员名单中、上报装有此卡片或尚未按新版同步本人记录的上架成员总数（非负整数），`my_installs` 为兼容旧看板的非本人上架记录，`my_all_installs` 为当前分享站对请求者本人计入的卡片编号并排序；卡片和技能包各按更新时间从新到旧，不含文件内容或其他成员的安装记录；新版分享站另有 `deliverables`：成品卡片列表（编号、上架人、名字、版本、说明、技能、文件数、大小、是否有配方、更新时间），不含文件和配方原文，旧看板忽略这一项；新版看板发送 `X-Skill-Pilot-Skill-Files: 1` 以查看逐文件上架的技能 |
| `PUT /api/installs/me` | `{"keys":["卡片编号",...],"include_mine":true}`；`keys` 必须是文字列表，`include_mine` 为可选布尔值；去重后保留当前目录中存在的卡片（未带 `include_mine:true` 时沿用旧规则过滤本人上架），整份替换本人记录，空列表删除本人条目；返回 `{"keys":[保留的编号，排序]}`，不存在或已下架的编号静默丢弃 |
| `PUT /api/listings/me` | `{"listings":[...],"packs":[...]}`；整批上架或替换本人的同名技能，可选的 `packs` 整体替换本人的技能包，和上架在同一次保存中生效；不带 `packs` 保留原包。返回每项的名称、卡片编号、时间及文件版本 |
| `PUT /api/packs/me` | `{"packs":[{"id":"acme","title":"Acme 技能包","skills":["acme-one","acme-two"]}]}`；整体替换本人的技能包，空列表全部拆开，不改卡片上架时间；返回 `{"packs":[...]}`，每包含 `key`、`id`、`member`、`title`、可选 `note`、`skills`、按相同顺序生成的 `cards` 和 `updated_at`；编号为 `pack:<成员编号>:<包编号>`，未变的包保留原时间 |
| `DELETE /api/listings/me/<技能名>` | 下架本人的技能并删除对应文件，同时移出技能包，包少于两个技能时自动拆开；未上架返回 `404`，本人其他上架仍需要它返回 `409` |
| `GET /api/packages/<成员编号>/<技能名>?version=<版本>` | 读取指定上架的最新文件；无文件或已下架返回 `404`，已换成其他版本返回 `409`；也可省略版本参数。逐文件上架的技能返回文件清单 |
| `GET /api/packages/<成员编号>/<技能名>/<内容编号>?version=<版本>` | 下载指定版本清单里的一个文件。请求须带版本，文件返回原始内容。版本已替换返回 `409`，已下架或文件不在清单中返回 `404` |
| `PUT /api/ratings` | `{"key":"卡片编号","stars":5,"text":"示例评价"}`；一人一条，可再次上传替换 |
| `DELETE /api/ratings` | `{"key":"卡片编号"}`；删除自己的评价，没有评价返回 `404` |
| `PUT /api/blobs/me/<内容编号>` | 请求体是一个技能或成品文件的原始内容（`Content-Type: application/octet-stream`），内容编号是它的 SHA-256；编号对不上返回 `400`，超过 50 MB 返回 `413` |
| `PUT /api/deliverables/me/<成品编号>` | `{"title":"成品名字","version":"v1","summary":"一句话说明","skills":["技能名"],"recipe":"复刻配方","files":{"index.html":{"sha256":"…","size":123}}}`；整份替换本人的同名成品。首页必须是 `index.html`；还有文件没上传时返回 `409` 和 `{"missing":["内容编号",…]}`，补传后再提交一次。每份最多 2,000 个文件、合计 200 MB，每人最多 50 份 |
| `DELETE /api/deliverables/me/<成品编号>` | 下架本人的成品，技能和成品都用不到的文件一起删除；没有这份成品返回 `404` |
| `GET /api/deliverables/<成员编号>/<成品编号>` | 成品的名字、版本、说明、技能、复刻配方、文件数和大小 |
| `GET /api/deliverables/<成员编号>/<成品编号>/<文件位置>` | 成品里的一个文件，按扩展名给出类型并加 `X-Content-Type-Options: nosniff`；支持单段 `Range` 请求（视频播放和拖动要用） |
| `POST /api/feedback` | 提交署名反馈，可选附带最多 3 张截图（PNG/JPEG/WebP，单张 ≤ 2 MB、合计 ≤ 5 MB，纯文字部分 ≤ 64 KB）；返回 `{"submitted":true,"duplicate":false,"feedback_id":"留底编号"}` 及已留底截图摘要 |
| `GET /api/feedback/<留底编号>/attachments/<内容编号>` | 仅允许原提交成员凭口令安全下载该条反馈已留底的截图；返回实际图片类型及 `Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'; sandbox`；记录不存在、非本人或已因容量上限淘汰时返回 `404` |

第一期的 `/api/shares*` 接口一律返回 `404`。

支持技能逐文件上传的客户端发送 `X-Skill-Pilot-Skill-Files: 1`。上架清单请求带 `Content-Length`，最多 **20 MB**。旧格式的 `source.files` 是含 base64 内容的列表，仍支持最多 300 个文件、解码后合计 5 MB。逐文件上传时 `source.files` 用 `{"SKILL.md":{"sha256":"…","size":123,"executable":false}}` 格式，根目录须有 `SKILL.md`，文件位置须在技能文件夹内。若返回 `409` 和 `missing` 列表，先向 `/api/blobs/me/<内容编号>` 补传每个文件，再提交原清单。两种格式对相同的文件算出同一版本。复制备份时保留整个分享站数据文件夹，供技能和成品共用的文件内容在 `deliverables/<成员编号>/blobs/`。

评价请求最多 **64 KB**，评分须为 1–5 的整数，评价和推荐语最多 200 字、不含换行或看不见的字符。请求超限返回 `413`，格式不对返回 `400`。所需技能必须在同一批上架，或已经由本人上架。整批校验通过才保存。

安装记录上报单独限制为 **65,536 字节（64 KB）**，同样带上 `Content-Length`、不接受分块发送。超限返回 `413` 并提示“上报内容超过 64 KB”，`keys` 不是文字列表返回 `400`。保存与成员管理、上架操作使用同一把锁，删除成员时也在同一次保存中删除其安装记录。

单独整理技能包的请求上限为 **65,536 字节（64 KB）**。每位成员最多 50 个包，每包 2–50 个不重复的本人上架技能，同一个技能最多在一个包里，飞书官方技能不能入包。包编号以字母或数字开头，最多 64 个字符，可含字母、数字、点、横线和下划线；包名按用户标签规则整理为 1–20 字，推荐语最多 200 字。未知字段丢弃，校验失败整份不保存。

上架只保留技能名称、中文名、一句话说明、分组、原说明、推荐语、所需技能和受支持的来源字段；文件只保留位置、内容和执行权限。版本、文件数和总大小由分享站计算。多余字段丢掉，不保存本机分配关系或账号设置。

加入请求也须带上 `Content-Length`，最多 **4096 字节**，不接受分块发送。缺少长度返回 `411`，超限返回 `413`，格式或名字不合要求返回 `400`。名字去掉首尾空白后为 1–40 字，不能换行或含控制字符，允许与其他成员同名。加入返回的口令只保存在本人电脑上，不在看板接口、日志或操作记录中显示。

开放的分享站可以先用下面的方式自助加入。返回内容含口令，用只有自己能读的临时文件接收，再读进变量，避免把它打印到终端或公共日志：

```bash
HUB_ADDRESS="http://<局域网地址>:8765"
HUB_JOIN_FILE="$(mktemp)"
curl --fail-with-body --silent --show-error -H 'Content-Type: application/json' \
  --data '{"name":"Acme 示例成员"}' --output "$HUB_JOIN_FILE" "$HUB_ADDRESS/api/join"
HUB_TOKEN="$(python3 -c 'import json, sys; print(json.load(open(sys.argv[1]))["token"])' "$HUB_JOIN_FILE")"
rm -f "$HUB_JOIN_FILE"
curl --fail-with-body -H "Authorization: Bearer $HUB_TOKEN" "$HUB_ADDRESS/api/me"
unset HUB_TOKEN HUB_JOIN_FILE
```

管理员可在终端交互输入口令检查接口；以下示例使用 bash，`HUB_ADDRESS` 换成自己的局域网地址：

```bash
HUB_ADDRESS="http://<局域网地址>:8765"
read -r -s -p '成员口令：' HUB_TOKEN
curl --fail-with-body -H "Authorization: Bearer $HUB_TOKEN" "$HUB_ADDRESS/api/me"
curl --fail-with-body -H "Authorization: Bearer $HUB_TOKEN" "$HUB_ADDRESS/api/catalog"
unset HUB_TOKEN
```

分享站只验证、保存技能信息和文件，不下载来源、不解开技能包、不安装或执行任何上传的文件。服务日志不记录口令、加入的名字、访问路径、评价或文件内容；请勿把添加成员时显示或自助加入时领到的口令保存到公共日志，也不要在打印命令参数的调试模式中运行上述检查。

## 接收署名反馈（可选）

同事遇到真实报错时点「反馈问题」，核对署名、脱敏诊断、选填说明及可选截图，再点「发送到飞书表格」。分享站按成员口令确定署名；看板不保存飞书接收地址，也不会自动上传。没有报错时，也可从「设置 → 诊断与备份」主动反馈。修改说明后需点「更新预览」再发送；支持在反馈窗口通过「选择截图」或剪贴板粘贴（`Ctrl+V` / `Cmd+V`）附带最多 3 张 PNG、JPEG 或 WebP 截图（单张不超过 2 MB、合计不超过 5 MB），提交前可预览与单张移除，仅上传图片内容本身，不含本机文件路径。

新版错误在发生时保存系统、Python 和当前进程的程序版本；新版文件已装好但尚未刷新时，仍记录正在运行的旧版。稍后修改设置或升级程序不会覆盖这份现场；工具与助手摘要仍在生成反馈时采集，诊断详情会注明时间。旧记录未保存的现场无法补回，会明确说明版本取自本次反馈。AI 连接失败还会附上官方服务类别（自定义地址隐藏）、程序识别到的代理配置、可信证书加载状态、证书校验编号、经过步骤和耗时；程序未发现代理不等于没有系统隧道，证书不受信任也不能单独证明代理有问题。握手失败时没有取得的证书签发者会明确标注，不猜测原因。

这些信息使用已有的「诊断详情」字段，已启用反馈的分享站和飞书表格无需改动。脱敏使用该次请求实际使用的设置，覆盖设置切换、域名大小写及国际化域名。只采集连接参数的安全摘要，不增加请求正文或密钥日志，不自动重试诊断连接、关闭证书校验或更改代理。

先在自己的飞书多维表格建一个问题表。建议先将下列列全部设为文本，避免日期、人员或单选字段的转换影响首次接收；需要分配处理人时另加人员列。

| JSON 字段 / 建议列名 | 内容 |
| --- | --- |
| error_id / 错误编号 | 本次错误编号 |
| fingerprint / 错误特征编号 | 同类错误归组依据 |
| status / 处理状态 | 初始为「待排查」 |
| occurred_at / 出错时间 | 原错误时间，主动反馈为空 |
| submitted_at / 提交时间 | 分享站生成的提交时间 |
| reporter / 反馈人 | 口令对应的成员显示名 |
| app_version / 程序版本 | 本机程序版本 |
| install_mode / 安装方式 | 源码或压缩包 |
| os / 系统 | 操作系统版本 |
| python_version / Python 版本 | 运行环境版本 |
| tools_summary / 外部工具 | 工具可用情况及版本 |
| agents_summary / Agent 摘要 | Agent 类型和技能总数 |
| source / 故障来源 | 后台、队列、页面等 |
| action / 出错操作 | 操作名称 |
| user_message / 错误概要 | 中文提示 |
| error_type / 错误类型 | 供维护者排查 |
| detail / 诊断详情 | 已脱敏的错误上下文（附带截图时末尾会自动追加 `[附带截图]` 说明，旧表不加新列也能看到） |
| user_note / 当时的操作 | 同事填写并脱敏后的说明 |
| attachment_count / 截图数量 | 可选新增文本列：本次附带的截图张数（无截图为 `"0"`） |
| attachments_summary / 截图说明 | 可选新增文本列：留底编号、分享站保存的文件名、格式、大小及下载接口路径（无截图为空） |

在多维表格的工作流或自动化入口，新建流程，以「接收到 webhook 时」为触发条件，接着选择「新增记录」，将收到的上述文本字段逐项映射到问题表。按飞书页面提示设置示例请求、测试并启用流程。配置方法见[飞书官方说明](https://www.feishu.cn/hc/zh-CN/articles/612376356355-设置接收到-webhook-时为工作流和自动化触发条件)。因为飞书多维表格 JSON webhook 仅接收扁平文本字段且分享站通常位于内网，截图原图保存在分享站本地 `feedback-attachments/` 目录，不会把原图直接塞进飞书 JSON 请求体；已上线旧表格无需立即改列即可正常接收，并在「诊断详情」末尾看到留底编号与文件名，也可随时新增「截图数量」「截图说明」两列单独映射。

将流程生成的接收地址只配置在运行分享站的服务器或 NAS 上。推荐通过该机器的服务配置注入 `SKILL_PILOT_HUB_FEEDBACK_WEBHOOK` 环境变量；也可以使用启动参数。下面全是占位示例，需换成自己的接收地址：

```bash
SKILL_PILOT_HUB_FEEDBACK_WEBHOOK='https://<你的自动化接收地址>' \
  python3 -m skill_pilot hub serve --data "/srv/Team Hub Data" --host 0.0.0.0 --port 8765
# 或在原启动命令末尾加：--feedback-webhook 'https://<你的自动化接收地址>'
```

接收地址必须使用 HTTPS，不能含账号密码，不接受本机或私网 IP，不跟随跳转，等待上限为 10 秒。地址不应写入仓库、日志或发给同事。未配置时，分享和商店仍照常工作，反馈窗口说明「管理员尚未启用飞书反馈接收」。升级并重启分享站后即支持截图附件（接口版本仍为 2）；旧版分享站缺少截图能力标记时，新看板仍可发送纯文本反馈或复制、导出诊断信息，并明确提示暂不支持随反馈上传截图。若分享站前有反向代理，需允许单次反馈请求体达到 8 MB。

分享站收到反馈后先校验图片魔数、格式、张数与体积，原子写入 `feedback-attachments/<内容编号>.<后缀>` 和 `feedback.json`，再发送扁平 JSON 到飞书。文字留底最多保留最近 200 条且总大小不超过 1 MB；截图留底总占用上限 50 MB，超出或对应记录被淘汰时自动按最早记录清理旧截图文件并保留文字留底，写入失败会回滚本次新建文件而不影响原有留底。备份包含服务端确认的成员编号、署名、发送状态和附件清单；同一成员 5 分钟内重复提交同一错误编号或特征编号不会重复转发。收到成功回执后，看板也保存已提交状态；转发超时或失败会保留备份并提示复制、导出，不把失败显示为成功。管理员可在数据文件夹查看 `feedback.json` 与 `feedback-attachments/` 中的留底截图排查，原提交成员也可凭口令通过 `GET /api/feedback/<留底编号>/attachments/<内容编号>` 安全下载本人提交的截图；程序不自动重发，以免超时后重复建记录。

首次配置后，用模拟故障走一次预览、附带截图与确认发送，核对表格新增记录的署名、说明、截图摘要和分享站留底文件。成功提示表示接收端已接受请求；新增记录是否完成仍由飞书流程的字段映射和运行结果决定。只读模式不能发送，离线、未连接团队分享或分享站连接失败时保留纯文本诊断复制与导出，并提示无法上传截图。
