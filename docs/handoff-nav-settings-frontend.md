# 交接：看板导航与设置页重排（前端）

2026-10-16，Claude 写给 DSH。对应 GitHub issue #35。先读仓库根目录 `AGENTS.md`、`DESIGN.md`（界面规则）、`PRODUCT.md`，再读本文件。

这次分两轮：**第一轮只出两版设置页样稿，不改看板**；用户从两版里挑一版后，Claude 再交给你第二轮，把它做进看板（导航三项居中、操作记录和诊断并进设置、改名、首次整理引导，见 issue #35 全文）。

## 背景（issue #35 摘要）

- 顶部导航现在五项：技能、清理、操作记录、诊断与备份、设置。改后只留**技能、清理、设置**三项，放在整个窗口宽度的正中间，SP 标志留在左边；右边的“可以管理技能”去掉（只读预览时仍显示“只读预览”）。
- 操作记录、诊断与备份并进设置。设置页现在是一条长页面，六块内容标题一样大、顺序没讲究；并进来以后更长，所以要分栏。
- “额外技能源”改名“其他技能文件夹”，说明写“SP 也会到这些文件夹里找技能。不填就不额外找。”，不再单独成块，放在 agent 一块的最下面。

## 第一轮要做的：两版设置页样稿

放在 `work/settings-prototype/`（`work/` 不进仓库）：`a.html`、`b.html`，必要时加一个两版共用的 `prototype.css`。用 `<link>` 相对引用 `../../skill_pilot/web/static/app.css`，沿用看板现有的类名和样式变量，让样稿看起来就是真看板；图标从 `index.html` 里把 `<svg class="icon-defs">` 那段图标定义整段拷进来用。每版都是完整的一页：新页头 + 设置页。

**两版共同的部分**

- 页头：SP 标志在左；技能、清理、设置三项在整个窗口宽度的正中间（不是标志右边剩余空间的中间），设置为当前页；没有右边的状态标记。
- 设置页左边一列小目录，分两组：
  - **常用**：AI 整理、agent、分享配置
  - **记录与维护**：操作记录、诊断与备份、版本
- 每块内容照现在 `index.html` 里对应部分的控件和文字做，数据全部用虚构的：
  - **AI 整理**：现在的“AI 服务”表单和“技能的中文名、说明和标签”合成一块（服务商、服务地址、模型、API key、保存并试一下；已整理多少个、整理剩下的、重新整理全部）。
  - **agent**：正在管理的 agent（虚构 3 个，如 Codex、Claude、Gemini，各带颜色点和技能数）、按文件夹接入、发现的新 agent（虚构 1 个），最下面是“其他技能文件夹”（一条虚构记录 + 输入框 + 记下）。
  - **分享配置**：现在“分享技能配置”的内容。
  - **操作记录**：现在操作记录页的时间线，虚构 4～5 条（如“给 Claude 加了 2 个技能”“更新了 3 个技能”），每条带撤销。
  - **诊断与备份**：现在诊断页的四个折叠块（版本差异、agent 与目录、其他发现、整理与还原），默认都收起；“迁移与还原”在样稿里就叫“整理与还原”。
  - **版本**：现在“SP 自身更新”的内容（已安装日期、检查更新）。
- 每块标题下一句大白话说明这块是干什么的。

**两版的区别**

- **A 版“一次一块”**：右边一次只显示目录里选中的那一块，点目录切换。默认选中 AI 整理。
- **B 版“整页连续”**：右边按目录顺序把所有块排下来，两组之间有组标题；左边目录固定不动，点目录滚到对应那一块，滚动时目录高亮跟着当前看到的块走。

两版都只需要很少的脚本（A 切换显示，B 滚动定位和高亮），不引入任何库。

**排版要求**

- 桌面窗口 1024 / 1280 / 1536px 宽都要排得下、不出横向滚动条；以 1280px 为主。不用做手机版。
- 照 `DESIGN.md`：字号、颜色、圆角、间距用现有变量；文字对比度不低于现在的标准。
- 用词照 `AGENTS.md`：中文大白话，说 agent 不说“助手”；不出现 symlink、diff、git、TOML、hash 这类词。

## 第一轮验收

1. 两个 html 文件直接用浏览器打开就能看（不需要启动看板），没有脚本报错。你没有浏览器，可以用 `node` 检查脚本语法；界面效果由 Claude 打开截图给用户挑。
2. 报告写在 `docs/nav-settings-frontend-report.md`：两版各自的结构、两版的区别、你在排版上做的取舍，以及做进看板时预计要改的地方（`index.html` 哪些区块搬到哪、`app.js` 里 `showPage`、跳到 `log` / `diagnostics` 页的入口等）。

## 边界

- 第一轮**不改** `skill_pilot/` 下的任何文件，不改测试。
- 样稿只用虚构数据，不读用户真实 home，不运行本工具对真实 home 的命令，不碰用户正在运行的看板。
- 不要 `git add`、不要提交。
- 不引入框架、构建工具和新依赖。

## 第三轮：Claude 验收后的修改意见（2026-10-16）

Claude 在两个模拟 home（从没用过 SP 的合成用户、`make-fake-home.py` 建的大技能库）上用浏览器走了一遍：首次整理、设置页六块、目录跳转和滚动高亮、旧地址、只读标记、1024 / 1280 / 1536px 都正常，全量 281 项测试通过。下面 7 处要改：

1. **还原后报错（要修）**：在设置 → 整理与还原点“还原到整理前”（“已有备份”里的“还原这份备份”、“整理好了”提示条上的“撤销”走的是同一条路）。后台已经还原成功，但 `finishMigration` 接着调 `refreshEverything()`，其中 `GET /api/table` 返回 409“请先完成首次迁移，再管理技能分配。”，页面于是弹出红色报错、整理与还原里出现同一句黄色提示、仍显示“已经整理好了”，技能页也不回到首次整理引导，要手动刷新页面才对。改法：`finishMigration` 先刷新 agent 状态、用 `renderMigrationStatus()` 判断是否已整理，只有已整理时才读技能表（和 `start()` 里的顺序一致）。改完要做到：还原后只出现“已经还原到整理前的样子”，没有报错；不刷新页面，技能页就回到首次整理引导；再走一次首次整理也能成功。
2. **引导里重复的一句**：引导开头已经写了“整理前会先备份，完成后能还原”，下面 `#migration-mode` 又写一遍“整理前会完整备份，完成后可以还原。”。能写入时引导里不显示这一行，只在只读时显示“只读模式下可以预览，不能整理。”。
3. **第 1 步按钮名字**：第 1 步按钮叫“开始整理”，可点了只是进入核对；最后确认框里的按钮也叫“开始整理”，用户会以为点了第一下就开始了。第 1 步按钮改成“下一步：核对”，第 2 步“确认整理”和确认框“开始整理”不变。
4. **分享配置块重复的说明没删**：第二轮已定删掉“导出分享给对方，或导入收到的清单，一次安装和分配。”这一句，现在还在。删掉它，原来挂在这句后面的 ⓘ 长说明挪到块说明或下面那行安全说明后面，内容不丢。
5. **引导卡片偏在左边**：1280px 下引导卡片约 580px 宽、靠左，右边一大片空白。改成在内容区里水平居中（最宽约 760px）。
6. **1024px 下诊断表格上方的工具条被截**：设置 → 诊断与备份 → agent 与目录，搜索框、“同时看内置和插件”、目录下拉排一行放不下，复选框文字被右边截掉。让这一行能折到下一行。
7. **`docs/STATUS.md`**：只把描述当前界面的旧说法改成新名字（如“设置 → SP 自身更新”改“设置 → 版本”、“额外技能源”改“其他技能文件夹”）；带日期的历史记录照原样保留。

要求同前两轮：不改 Python 文件和测试，不对真实 home 运行本工具，不要 git add、不要提交。改完 `node --check`，相关测试文件自测，能用无头浏览器复现第 1 条并确认修好最好。报告在 `docs/nav-settings-frontend-report.md` 末尾追加“第三轮”一节，逐条写怎么改的。
