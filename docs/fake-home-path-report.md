# 报告：模拟环境脚本去掉写死的个人文件夹（issue #46）

> 2026-10-16。Codex 按 Claude 的交接改代码和测试（交接文件按规则不进 PR）；Codex 跑全量测试时任务因用户关机暂停，报告由 Claude 审查、验收后补写。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| [make-fake-home.py](../scripts/make-fake-home.py) | 复制清单里删掉写死的维护者私人技能文件夹。技能链接指向主目录里其他文件夹时，靠现有的“顺着链接复制目标”带过去；用户记下的“其他技能文件夹”照旧通过 `extra_source_paths()` 复制。 |
| [verify-m2.py](../scripts/verify-m2.py) | 核对清单里删掉同一条路径；记下的其他技能文件夹仍在清单里。 |
| [test_store.py](../tests/test_store.py) | 新增 `test_simulator_copies_link_dependencies_and_optional_extra_sources`：来源主目录在路径含空格的临时目录里，一个技能是绝对链接、一个是相对链接，分别指向技能根以外的文件夹；分有、没有 `extra-sources.json` 两种情况。核对两个目标被复制、链接落在模拟环境内部、记下的文件夹只在设置了时才复制、没链接也没记下的文件夹不复制、复制清单里没有 `Developer/` 开头的条目。 |

删掉这一条之后，通用逻辑没有发现漏洞，没有改其他代码。

## 验收结果

- 全量测试：跟上最新 main 后 303 项通过（Python 3.11）。
- 新测试在改动前的代码上失败（两种情况都因复制清单带着那条私人路径），改动后通过。
- 用那个私人文件夹的名字搜 `scripts`、`skill_pilot`、`tests`，无结果。当时开发历史文档仍记着这条路径；后续已改成泛指。
- 手动核对：在系统临时目录里另造路径含空格的合成主目录，有一个绝对链接技能、一个相对链接技能、一个只在设置里记下的文件夹、一个都不沾的文件夹，运行

  ```sh
  python3.11 scripts/make-fake-home.py "<临时目录>/fake home" --source-home "<临时目录>/source home"
  ```

  没有设置时，复制清单只有 `.skill-pilot`、各技能根和 `.agents/.skill-lock.json`；两个链接目标出现在 `link_dependencies` 里并被复制；绝对链接改写到模拟环境内，相对链接保持原样；没有链接逃出模拟环境。有设置时，记下的文件夹也出现在复制清单里并被复制。两种情况下都不沾的文件夹都没有复制。
- 没有对真实主目录运行脚本，没有运行 `verify-m2.py`，没有碰用户的技能库和正在运行的看板。
