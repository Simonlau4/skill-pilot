# 共用技能目录的 agent 接入修复

2026-10-16，Codex，#60。验证使用系统临时目录中的合成用户，未操作真实技能库或正在运行的看板。

## 原因

旧页面把 `must_select_together` 中的目录读取关系当作本次新增名单，直接提交整组成员。因此接入 Cursor 时也提交了已经接入的 Codex、DSH，后台的重复接入保护报出“Codex 已经接入了”。

另一个通用缺陷是页面只取第一组关系。同一个成员读取两个目录时，可能分别关联另外两位成员，第一组并不能表示完整的待接入名单。首次整理的逐组勾选也有相同的遗漏风险。原有检查覆盖了两位成员一起首次接入，但没有覆盖部分成员已经接入与多组连续关联。

## 修复规则

- 保留 `shared_groups()` 表示每个共用目录的实际读取关系，继续用于技能分配的限制与说明。
- 新增 `enrollment_groups()` 专门计算待接入组：先去掉已接入成员，再把尚未接入成员之间重叠的组完整合并。未检测到且未明确选择的成员不自动带入。
- 已接入成员已经满足接入条件，也不作为桥梁去带入其另一目录中的无关待接入成员。
- 建议、忽略后重接和手动添加只提交用户选择的对象；后台在只读预览中补齐必须新增的关联成员。预览显示完整名字和目录，用户确认后才写入。
- 命令行接入也使用后台生成的完整名单，预览文字逐一列出会接入的成员。
- 确认时保留原始选择和手动填写的信息，由后台再次计算并核对预览。检测结果或目录改变会要求重新预览；明确重复接入与不安全目录仍然拒绝。
- 首次整理的联动勾选与后台完整性校验使用同一套待接入分组，连续关联的成员可一起勾选、一起取消。

## 验证

最终全量 339 项测试全部通过，页面脚本检查与修改检查通过。

新增 12 项回归检查，其中一项穷举任意四位成员的 64 种共用关系与 16 种已接入状态，共 1024 种组合，验证分组完整、互不重叠、不含已接入成员，并核对首次整理的完整性保护。

其余检查覆盖 Cursor 与已有 Codex、DSH 的组合、两处目录连续关联、独立成员、已接入成员作为分界、忽略后随关联接入、手动档案、重复接入、预览后新检测到成员、自动带入成员的目录边界。接入和撤销同时核对原有文件与技能可见性。页面脚本检查验证按钮只提交用户选择、确认保留原始手动信息、预览使用后台提供的名字；命令行实际完成完整名单预览、接入与撤销。

在不同安装位置的程序副本和含空格的模拟用户目录中，浏览器实际完成：

1. Cursor 单独预览、接入、撤销、再次接入与撤销。
2. 点击 Alpha，完整预览并接入 Alpha、Beta、Gamma；独立 Delta 保留在候选列表；撤销后原有文件与可见性一致。
3. 手动填写尚不存在的技能文件夹，预览、接入与撤销。
4. 全新用户从关联组的一端取消、另一端重新选中，三位成员完整联动；取消独立成员后完成首次整理，只有所选三位进入管理。

修复针对通用接入选择与确认逻辑，不改变技能分配规则或程序更新流程。
