# SP 自身更新验收

日期：2026-10-15。代码实现、260 项单测和浏览器完整流程验收已完成。本次发布包含程序、启动入口、回归检查和公开使用说明。

## 使用方式

打开“设置 → SP 自身更新”，点击“检查更新”；有新版时点击“一键升级”，装好后点击“刷新生效”或刷新浏览器。正在执行的操作先完成，原地址、会话和技能库保留。

旧版用户首次需要获取含此入口的新版，运行一次 `sh scripts/build-app.sh`；更早的不支持刷新切换的看板需要正常重开一次。之后普通更新无需 agent 或再次运行安装命令。安装和更新步骤见 [README.md](../README.md)。

## 实现范围

- 来源固定为官方 `Simonlau4/skill-pilot` 的 `main`，检查时锁定版本；接口不接受任意来源或项目位置。
- 下载在系统临时目录准备，核对必要文件、全部 Python 程序语法及启动入口和后台能否加载。未完成检查时不替换原程序。
- 源码安装保留版本历史，只接受可直接升级且没有本地改动的安装；ZIP 安装按安装时的文件清单核对，保留后来添加的其他文件。更新后两种方式都可再次检查和升级。
- 程序文件或同名文件发生变化时停止，保留原文件。源码版本在下载准备完成后再次核对，恢复时也保留新的本地改动。
- 更新时同步安装当前用户的桌面应用和命令行入口，复用正在运行的 Python 和该用户的工具环境，不依赖维护者的目录。
- 替换前备份程序文件和两个启动入口；安装失败自动恢复。若文件夹已无法写入导致恢复失败，保留独立的恢复文件夹，并在页面给出位置。
- 技能库、分配、账号密钥及旧用量文件不参与程序替换或备份。只读模式可检查，不可升级。
- 升级在后台进行，刷新后仍能看到进度；切换程序等待现有请求、技能更新和 AI 整理完成。升级期间暂停新的写入。

## 已完成的验证

测试均使用系统临时目录内的新模拟用户和独立项目，项目路径包含空格、单引号及字面量 `$()`。没有操作真实技能库或用户正在运行的看板。

- 260 项单测通过，包含本次新增的 17 项；`node --check skill_pilot/web/static/app.js` 和 `git diff --check` 通过。
- 两种安装方式都用真实的独立来源准备新版、更新文件和启动入口，并实际运行后台：升级后仍使用原地址、原会话和原进程，刷新后读回新版标记；再次检查正确显示已是最新版本。个人技能库前后指纹一致。
- 验证下载失败、新版无法加载或缺文件、本地改动、下载后文件变化、新文件重名、文件指向其他位置、只读模式、错误来源请求、未确认请求、过期版本选择。
- 验证安装途中失败后，程序、安装记录和桌面入口恢复原样，随后可重试成功；下载准备期间产生的新改动会保留。
- 验证已有任务先完成、升级期间新的写入被暂停、进度接口不返回下载目录或程序文件内容。
- 1280 × 720 浏览器中实际完成“检查更新 → 一键升级 → 刷新生效”，读回“SP 已升级到最新版”，设置页位置保留，页面无脚本错误。随后再次升级仅有界面变化的版本并刷新生效；本地改动提示及恢复后重新检查也通过。
- 另从官方 GitHub 实际下载并检查公开新版，验证无登录交互、下载文件完整、当前版本保持原样；未在维护者的真实环境执行升级。

## 公开下载验收发现的 ZIP 清单修复

主体功能发布后，实际从 GitHub 下载源码和 ZIP：全部 138 个文件的内容、执行权限一致，源码安装的桌面入口、命令行和官方更新检查通过；ZIP 首次安装却误报“有新版”。原来的模拟来源没有包含根目录的 `skill-pilot` 启动文件，因此未覆盖此问题。

修复将这个启动文件纳入 ZIP 安装清单，并把真实启动文件补进测试夹具。原“全新 ZIP 已是最新版”的检查在修复前失败，修复后通过；17 项升级专项和 261 项全量检查通过，同一组检查也覆盖后续更新、失败恢复与重试。公开 ZIP 按修复后的清单逻辑重建安装记录后，桌面入口、命令行和官方更新检查均通过，正确显示为最新版。

本次修复通过独立分支和 PR 提交，尚未合并到 `main`。已经安装初版 ZIP 的用户，需要在修复版合并后先手动获取新版文件，再运行一次安装命令；源码安装不需要这次修复操作。

复现自动检查：

```bash
PYTHONDONTWRITEBYTECODE=1 python3.11 -m unittest tests.test_self_update -q
PYTHONDONTWRITEBYTECODE=1 python3.11 -m unittest discover -q
node --check skill_pilot/web/static/app.js
git diff --check
```
