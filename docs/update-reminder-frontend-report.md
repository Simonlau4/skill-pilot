`app.js` 里动到的函数：

- 新增 `railUpdateNote()`：按 `programUpdate` 拼出左栏那张卡片；`renderRailNotes()` 把它放在“发现新 agent”卡片上面。同一份进度也画设置 → 版本，在哪边升级两边都跟着变。
- `renderRailNotes()`：改成先收集所有卡片再一次写入，并用 `railNotesHtml` 记住上次的内容，没变就不重画（自动检查在跑时每 1.5 秒读一次进度，不重画就不会把正在点的按钮换掉）。
- `renderProgram()`：末尾调 `renderRailNotes()`；自动检查正在跑时不写页头任务条。
- `programAction()`：新增 `programFailedAction`，记住本次打开页面里哪一步没成；升级失败时左栏留一张带原因的卡片和“升级”按钮可以再试，开始新一次动作时清掉。
- `start()`：打开页面就调一次 `refreshProgramUpdate()`（不 await，不拖慢首屏）。
- `#rail-notes` 的点击处理：卡片上的“升级”走现有 `programAction('apply')`（等手上操作完成、失败自动恢复原版这些保护照旧），“刷新生效”就是刷新页面。
- `WRITE_LOCK_SELECTORS` 增加 `'#rail-notes button'`，任何写入期间左栏的按钮一起禁用。

## 五条要求分别怎么做到

1. **打开页面读一次进度**：`start()` 里调 `refreshProgramUpdate()`；自动检查还在跑时沿用原来每 1.5 秒的轮询，查完卡片自己出现，不用手动刷新。同一次运行里刷新页面、开新页面都只读进度，不会重新发起检查（检查由后台在启动时做一次，接口只回结果）。
2. **左栏提醒**（和“发现新 agent”同款 `.rail-note` 卡片，排在最上面，只读预览不出）：
   - 有新版（`available` 且能写入）：标题“SP 有新版”，小字“新版 2026/10/16”（取 `latest`），按钮“升级”。
   - 升级中（`running` 且 `phase` 为 `apply`）：“正在升级…”，按钮不可点。
   - 升级好了（`phase` 为 `ready`）：“升级好了”，按钮“刷新生效”。
   - 升级失败（页面记下这次失败的是升级，`phase` 为 `error`）：标题“升级没完成”，小字是后台给的原因，按钮“升级”可以再试。
   - 已是最新、还没查到、正在检查、只读预览：不显示这张卡片。
3. **自动检查不打扰**：`renderProgram()` 里，`phase` 为 `check` 且 `automatic` 为真、又不是用户自己点的那次时，不往页头任务条写“正在下载并检查新版…”；手动点“检查更新”照旧显示。左栏在检查期间不出现卡片，查完有新版才出现。
4. **设置 → 版本**：版本信息和“检查更新”按钮照旧。自动检查失败时后台给的是中性状态（`phase` 为 `idle`、`error` 为空、说明为“还没查到新版信息”），页面把它当普通说明显示，红字因为 `error` 为空而隐藏。
5. **用词与文档**：卡片里只有“新版”“升级”“刷新生效”，没有 GitHub、提交、版本号这类说法；`DESIGN.md`、`README.md` 各补一句。左栏卡片和设置用同一份 `programUpdate`，两边不会互相矛盾。

2. 点“升级”：真实走完下载、替换、恢复保护；卡片变成“升级好了 / 刷新页面就能用新版 / 刷新生效”，任务条空。

4. 再开一个新页面（等于“再次打开”）：依然没有卡片，任务条没有自动检查的进度。
5. 注入状态核对另外几种：自动检查中 → 无卡片、任务条隐藏；手动检查中 → 无卡片、任务条显示“正在下载并检查新版…”；自动检查失败的中性状态 → 无卡片、任务条隐藏、设置里写“还没查到新版信息”且没有红字；只读预览 + 有新版 → 无卡片；升级失败 → “升级没完成”加原因和可点的“升级”。
6. 维护者场景：直接在本副本（有未提交的本地改动）里用新模拟 home 跑真实 `python3 -m skill_pilot ui`，自动检查静默失败，左栏没有卡片、任务条空、设置里是中性说明，没有报错。（“断网”走的是同一条中性分支，页面这边和上一条一样什么都不显示；后台的网络失败分支由 `tests/test_auto_update_check.py` 覆盖。）
