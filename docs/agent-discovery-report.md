# Cursor、豆包工作和 WorkBuddy 识别

2026-10-16，#50。

这三款应用已经装好、还没有用户技能时，旧版接入列表可能为空：旧发现方式依赖技能说明文件，已知 agent 的建议也要求技能目录先存在。豆包工作的用户目录在应用数据深处，既不属于旧档案，也不符合隐藏文件夹下的通用发现规则。

## 当前行为

- 按系统或当前用户 `Applications` 里的应用、产品配置目录或已有命令识别，首次整理与设置页都可以接入零技能的 agent。
- 扫描只读取；接入、分配与撤销沿用原有预览、备份和操作记录。完全空的技能库也能完成首次整理。
- Cursor 同时读取自己的用户技能与共享目录。已经安装或已接入、且共用目录的 agent 仍须一起接入；没有装的软件不再成为新用户接入的前提。
- 已经用自定义档案接入的 Cursor 或 WorkBuddy 保留原来的目录和读取方式，不重复登记，不自动扩大范围。
- 模拟用户只查自己的应用位置与配置，不把开发者电脑上的应用和命令当作模拟用户的软件。即使修改了模拟用户的 `HOME` 也保持隔离。

## 用户技能与只读内容

下列位置都相对当前用户的主目录解析，与用户名、项目位置无关。

| agent | 用户技能 | 只读内容与依据 |
| --- | --- | --- |
| Cursor | `.cursor/skills`、`.agents/skills` | `.cursor/skills-cursor` 和插件另列。用户目录与递归读取依据 [Cursor 官方文档](https://cursor.com/docs/skills)。 |
| 豆包工作 | `Library/Application Support/DoubaoWork/Default/.doubaowork/agent_mode/workspace/.user_skills` | 同级 `.skills` 为预装内容，只查看。已核对桌面应用 2.25.18 的目录，以及随产品分发的 `skill-creator-for-work` 对 `workspace/.user_skills` 的说明。主目录下的 `DoubaoWork/skills` 空文件夹不作为应用读取用户技能的依据。 |
| WorkBuddy | `.workbuddy/skills` | 市场、插件与连接器另列。用户目录已核对产品分发的 `find-skills` 指引；安装与开关行为见 [WorkBuddy 官方说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)。 |

产品内的独立技能开关没有接入 SP；数量按目录与已知手动调用标记统计。豆包工作的本次支持针对上述 macOS 桌面应用目录；改变内部目录的其他版本需要重新核对。未启动三款应用执行技能，不把文件可读与分配检查称作产品内调用成功。

## 验证

10 项新增回归覆盖空用户隔离、只安装应用、只有配置目录、不同应用位置、三款各自从零完成首次整理与分配后撤销、内置目录保护、旧自定义记录、已有用户批量接入及撤销、共享目录约束、忽略空 agent 后恢复。

在系统临时目录中建立空来源，通过公开的模拟用户脚本创建新 home，再把源码放进含空格的另一位置。使用新 home 运行公开安装命令，生成该模拟用户自己的应用与命令入口，再从生成的命令入口打开看板。浏览器实测：首页只列 Cursor、豆包工作、WorkBuddy，默认全选；0 技能预览通过；确认后显示「整理好了」；设置页读回三款均已接入。自带管理技能自动安装到这三款的独立用户目录。没有复制真实技能、设置、账号或旧用量文件。

全量 313 项测试、页面脚本检查通过。真实环境只读对比：旧接入建议没有三款，新规则能列出三款；原有技能目录、统一仓库、来源记录与配置前后 8596 项指纹一致，未操作用户正在运行的看板。

本修复通过独立分支交付，合入公开正式版后，新安装或升级到该版本的用户才能获得上述行为。
