# Agent 扫描优化验收

2026-10-16，任务 #55。当前为提交审查版本。

## 用户看到的变化

- 设置 → agent 标题右边增加“重新扫描 Agent”。新装软件后可以立即检查，无需重启看板。
- 扫描中按钮禁用，状态行显示进度；完成后显示发现结果和检查时间；失败保留旧名单，可以重试。
- 打开看板先显示保存的名单，再在后台检查应用、已有配置目录与常见技能目录。
- 新发现项由用户决定接入或忽略，扫描不改变技能分配。候选项不预先计算技能数量，接入时再核对。

## 实现范围

- 发现结果保存在当前用户的 `.skill-pilot/agent-discovery.json`，只包含 Agent 名称、编号、相对技能目录、识别依据和检查时间，不含技能正文或账号设置。这个文件只是可重建的发现结果，接入和忽略仍以原来的登记为准。
- 自动检查应用和约定目录，也验证上次发现的较深目录是否还在；手动扫描进一步查主目录隐藏文件夹，最多四层。不进入项目、参考资料、缓存或已知内置与插件目录，不沿外部目录链接搜索。
- 看板读取 Agent 名单时不再调用完整技能盘点、内容指纹或分配核验。需要写入的接入、忽略、不再管理仍走原来的预览和确认。
- 启动不预先生成完整诊断；进入“诊断与备份”或使用原有盘点操作时才读取。技能扫描本身的范围和判断没有改变。
- 扫描只有一个工作线程；并发请求沿用当前扫描。错误不会覆盖已保存结果；只读模式可检查但不写缓存。
- 本任务未修改程序版本检查、更新提示或更新生效逻辑。

## 验收结果

`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -q`：326 项全部通过。`node --check skill_pilot/web/static/app.js` 和修改格式检查通过。

新增回归覆盖：

1. 空用户环境不会误认维护者的软件；Cursor、豆包工作、WorkBuddy 只有应用、没有技能时仍能发现。
2. 发现 Agent 不读技能内容，不做完整技能盘点和分配核验。
3. 常见目录自动发现；较深目录手动发现；重开后保留结果，再次检查会核对目录是否仍在。
4. 缓存损坏或含越界目录时忽略；只读模式不写；缓存不能写到主目录之外。
5. 原接入、自定义目录、忽略、共享目录和技能分配保持。
6. 运行中增加 Agent，点扫描即列出；重复请求不并行；失败保留原结果，重试成功。
7. 完整技能诊断只在请求时读取，并复用结果。

升级流程原有两项进程回归也通过：除允许重建的 Agent 发现结果外，个人配置和技能状态继续逐项比较，确保没有被程序升级改动。

## 安装与浏览器

在系统临时目录中的全新模拟用户与含空格的独立项目位置验收，没有复制真实技能、账号或密钥。安装器按其实际使用方式显式模拟当前用户目录，再从生成的命令入口启动：

- 首次整理列出三款 Agent，默认全选；空技能库可完成整理。
- 设置页读回三款已接入，扫描入口和检查时间可见。
- 看板运行中增加一个四层目录的模拟 Agent；点击扫描时按钮禁用，完成后出现“发现 1 个新 Agent”和接入、忽略按钮。
- 结束本次后台后重新启动，较深目录的发现结果仍在；键盘回车可触发扫描，技能页未应用的选择在扫描前后保持。
- 浏览器未记录脚本错误或警告；实际页面截图核对按钮、状态和名单位置。

## 性能与真实环境边界

先前的只读检查约 36.8 秒，其中约 32.9 秒用于广泛遍历应用数据。新逻辑在同一电脑只读对照：自动检查约 0.036 秒，手动扫描约 0.115 秒；两条检查的范围不同，这不是完整技能扫描的提速结果。

真实环境检查前后指纹一致，没有接入、分配或改写真实技能，也没有重启用户正在运行的看板。功能验收以独立模拟用户和安装位置为依据；本机对照只补充性能与识别证据。
