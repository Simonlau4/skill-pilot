# 看板体检：问题清单（2026-10-13）

按 Impeccable 的“挑毛病”（critique）方法做，界面类型按它的“干活界面”（Operate：看板、设置、工具）来评。

> ⚠️ 简化版体检：没有运行 Impeccable 自带的自动检查程序（项目规矩不运行技能里的程序），也没有分成两路独立检查；全部由 Claude 在一个对话里看完，再按它的规则逐条对照代码。

- 看的是什么：用 `scripts/make-fake-home.py` 从真实技能库复制出的模拟环境（131 个技能、5 个 agent，中文名和分组齐全，不含设置和 key），在 1280×800 窗口里逐页操作；另看了手机宽度。前端代码 `skill_pilot/web/static/` 对照着读。
- 没覆盖到：没有实际跑“检查更新”（要联网查 130 个技能）；出错路径只看了代码。模拟环境读不到用量，所以“最近使用”全是“统计不到”，这一点不算问题。
- 实际操作过的：展开分组、勾选（带出依赖）、应用、确认、撤销提示、打开详情、按 Esc 关闭、切换全部 6 个页面。

## 是不是“专门为这个产品做的”

不像。配色几乎就是 Notion 的（暖灰底 `#F7F6F3`、深灰字 `#2F3437`），加上系统字体、细边框、分段筛选按钮，换成任何一个“后台表格”都成立。

这个产品最核心的东西是“一份技能库，分给几个 agent”和“说明字数占了多少上下文”（最初四个问题之一）。前者只是一张普通勾选表，后者只是一串数字：“说明 28,374 字”。这串数字是多还是少、该不该清理，页面一句都没说。最该有特色的地方，现在是最平淡的地方。

## 整体印象

交互的骨架是对的：勾完一起应用、能撤销、改了没应用的有标记、顶部实时预览数字。粗糙主要在三处：
1. 首屏堆满了“登记信息”，没有“该处理的事”；
2. 后台的概念（文件路径、链接、共用文件夹）直接摆给你看；
3. 字太小太灰，所有东西一样重。

最大的机会：把首页从“登记簿”改成“待办”。

## 做得好的

- **所有写入一个套路**：改了先标“待应用”，底部汇总改了几处，再确认，做完给能撤销的提示。顶部 agent 栏实时显示“应用后 55 个 / 15,919 字”，改之前就知道后果。这套要保留。
- **技能变得看得懂**：中文名、一句话说明、英文原名小字，按用途分组、默认收起。131 个技能不再是一面英文墙。
- **说实话**：“统计不到用量：还没找到读取它使用记录的办法”“只检查，不会自动安装”“完成后可以在操作记录里撤销”。

## 主要问题（按轻重排）

### [P1] 确认框先列一堆文件路径，真正要做的事被挤到下面

- **现象**：只是“给 Claude 加 2 个技能”，确认框却先列出 7 条“受影响的文件”，例如 `~/.codex/skills/agency-router/SKILL.md.bak.20260716-154249`、`~/Documents/Example-Notes/notes/sample-map.md`，然后才是“给 Claude 加上 2 个”。底部已经按过一次“应用”，这里还要再按一次。
- **为什么要紧**：你看不懂这些路径，也没法据此判断，只能闭眼点“应用”。久了就会养成不看确认框的习惯，真正危险的那次也会点过去。同时也违背了“不想逐条确认”。
- **怎么改**：确认框第一句写清结果（“Claude 会多 2 个技能，其中 1 个是自动带上的”）；文件路径收进“技术细节”或干脆不显示。能撤销的“加技能”不弹确认框，直接做、给撤销提示；只有撤下、清理、不再管理这类操作才弹框。
- **Impeccable 命令**：`clarify`、`distill`

### [P1] 自动带上的依赖技能，被勾在你看不见的地方

- **现象**：在“开发助手”组勾选“多智能体分派”，它依赖的“营销技能路由”在另一个收起的组（广告营销）里被一起勾上。只有底部一行小字提到，那个组的数字悄悄变了。
- **为什么要紧**：你以为改了 1 处，实际改了 2 处。想取消自动带上的那个，得先猜它在哪个组。
- **怎么改**：底部改动栏列出这次的每一项改动（技能名、给哪个 agent、是不是自动带上的），每项都能单独取消；或者加一个“只看待应用”的筛选。
- **Impeccable 命令**：`shape`、`layout`

### [P1] 首屏信息太多、没有主次，也没有“该处理的事”

- **现象**：第一行技能出现之前，有标题、副标题、6 个页面按钮、状态标签、5 张 agent 卡片（每张有个数、字数、生效方式）、新 agent 横幅、搜索框、5 个筛选、2 个按钮和一句操作说明。第一行技能出现在屏幕将近一半的位置。组标题行还带着两列空着的“最近使用”“说明字数”。字号和灰度基本一样。
- **为什么要紧**：打开看板，第一眼不知道该看哪儿。真正需要你动手的事（有更新、有该清理的、发现新 agent）分散在不同页面和横幅里。
- **怎么改**：首页顶部只放“需要你处理的”几件事，每件一个按钮（例如“3 个技能有新版”“5 个技能 60 天没用”“发现新 agent：Trae”）；agent 栏缩成一行；组标题行去掉空列。“说明字数”改成能看懂的形式，比如每个 agent 一根条，标出偏多还是正常。
- **Impeccable 命令**：`distill`、`layout`

### [P2] 字太小太灰，读中文吃力

- **现象**：技能说明是 12px 灰字（#787774），在白底上对比度 4.48；格子里的备注 11px；灰字放在页面底色上只有 4.14。样式里有 38 处用到 12px 以下的字号。
- **为什么要紧**：看板上最要紧的内容就是“这个技能干什么的”，现在恰好是最难读的那一行。笔画多的中文在 11～12px 很费眼。
- **怎么改**：正文 14～15px；说明 13px，灰度加深到对比度 5.5 以上；只留两三种灰。
- **Impeccable 命令**：`typeset`

### [P2] 后台概念直接摆给你看

- **现象**：
  - 详情面板显示“存放位置 `~/.skill-pilot/store/context-pack`”“各 agent 里的入口 … 链接到统一仓库”；
  - 同一个技能，表格写“没分配”给 Codex，标签写“Codex 里停用了”，入口列表里又有两条 Codex 的路径；
  - 设置页每个 agent 下面列文件夹路径；
  - 操作记录里，只给 Claude 加了 2 个，“影响”却写 Antigravity、Claude、Codex、DSH；已经做完的事写成“将给 Claude 加 2 个”。
- **为什么要紧**：页面的说法和你脑子里的样子对不上，就要花力气去翻译，还容易怀疑是不是出了问题。
- **怎么改**：按结果说，例如“Codex 看不到它：Codex 和 DSH 用同一个文件夹，所以帮你在 Codex 里关掉了”。路径都收进“诊断与备份”。操作记录用过去时（“给 Claude 加了 2 个”），“影响”只列真正多了或少了技能的 agent。
- **Impeccable 命令**：`clarify`

## 用三种人的眼光走一遍

- **你自己（不写代码，管 131 个技能、5 个 agent，不想逐条确认）**：勾一个技能，被问两次，第二次是看不懂的路径；带出的依赖不知道在哪；进详情看到 `~/.agents/skills` 和“链接”。想知道“该清理什么”，得自己去另一页。
- **熟手（想快）**：没法用键盘打开技能详情（整行能点，但不是按钮，Tab 键到不了）；每次应用都要等好几秒，期间整页变灰不能动；依赖只能从 130 项的下拉框里挑。
- **靠键盘或读屏的人**：勾选框有清楚的名字（“Claude 使用 妙搭应用开发”），这点好；但技能行打不开；“分配已经应用”这类提示没有告诉读屏软件改了什么；灰色小字对比度低于标准。

## 小问题

- 应用时在 agent 栏下面插入一行“正在应用…”，整页往下跳一截；完成后又跳回来。
- 撤销提示从右下角弹出，会盖住表格最右两列和详情面板底部。
- 详情面板一次性展示原文说明、来源、位置、5 个 agent 的用量表、入口路径、依赖和 130 项下拉框，太长。
- 操作记录里几周前的记录，和刚刚的一样挂着醒目的“撤销”，没说撤销旧记录会不会影响之后的改动。
- 切页面不改地址；刷新后总是回到技能页，展开的组和筛选都丢了。
- 设置页 5 个“不再管理”按钮和普通按钮一样，挨个排着。
- 清理页在读不到用量时也写“60 天内都用过”（模拟环境里看到的；真实环境里读不到用量的 agent 同样可能出现）。
- 手机宽度下，页面按钮压住标题，“检查更新”这类按钮一个字一行。看板主要在电脑上用，这条最不急。
- 没有深色模式，也没有“减少动画”的设置（动画本来就少，影响不大）。

## 值得想一想的

- 如果首页只回答一个问题“今天有什么要我处理的”，技能总表是不是可以退到第二层？
- 技能 × agent 的勾选表，是不是一定要一次摆出 5 列？换成“选一个 agent，看它有哪些技能”，会不会更像你脑子里的样子？
- 能撤销的操作都不弹确认框，会不会更安心而不是更危险？

## 结论：重做外观和页面组织，保留交互骨架

“勾完一起应用、待应用标记、能撤销、实时预览数字”这套是对的，也是之前花力气做稳的（还有长时间开着不断线、勾选不等待）。问题集中在首页放什么、用什么话说、字怎么排，这三样在现有样式上修修补补效果有限，适合按 Impeccable 的“重做”来：旧样子当反面参考，换一套新的。
