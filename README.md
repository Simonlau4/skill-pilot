# Skill Pilot · 本机技能管理

统一管理本机多个 agent 的技能：每个技能只存一份，决定哪个 agent 能用哪些，按需检查上游更新，撤下不需要的。内置 Codex、Claude、Antigravity、DSH、Cursor、豆包工作和 WorkBuddy 的接入规则，也可在看板接入发现的其他 agent。

## 安装

当前支持 macOS 本地桌面。需要 Python 3.11.4 或更高版本，以及可用的 Git；飞书技能更新另外需要 Node.js 和 npm。Python 最低版本用于支持下载文件的安全解包，见 [Python 官方说明](https://docs.python.org/3.11/library/tarfile.html#extraction-filters)；飞书工具的依赖与账号配置见 [飞书官方安装说明](https://github.com/larksuite/cli#installation--quick-start)。

从 GitHub 获取源码后，在项目文件夹运行：

```bash
git clone https://github.com/Simonlau4/skill-pilot.git
cd skill-pilot
sh scripts/build-app.sh
```

也可下载并解压 GitHub 的源码 ZIP，在解压出的项目文件夹运行最后一条命令。安装器会识别当前用户可用的 Python 和工具位置，生成应用与命令行入口；用户名、项目位置和路径中的空格均可不同。若有多个 Python，可用 `SKILL_PILOT_PYTHON="/你的路径/python3" sh scripts/build-app.sh` 指定一个符合要求的版本。

双击当前用户 `Applications` 文件夹里的 **Skill Pilot.app** 打开看板，按页面提示选择要接入的 agent、核对首次整理结果。项目文件夹需要保留；移动后在新位置重新运行安装命令。命令行可用 `~/.local/bin/skill-pilot`，或把 `~/.local/bin` 加入自己的命令搜索路径后用 `skill-pilot`。

打开和刷新看板都先到首页：查看技能总览、各 agent、要处理的事和最近改动，点一下前往对应页面。首次使用按首页提示到技能页做整理。

Cursor、豆包工作和 WorkBuddy 会按已安装应用或各自的应用数据识别，还没装过用户技能也会显示。已经整理过的用户可从首页「发现新 agent」提醒前往设置，再点「接入」，后台会读取并接入。应用放在系统或当前用户的 `Applications` 文件夹时可直接识别；放在其他位置时，先正常打开一次该应用，让它建立应用数据，再打开或刷新 SP。内置技能、市场、插件和连接器只查看；豆包工作使用桌面应用数据中的用户技能目录。目录依据与验证范围见 [agent 识别说明](docs/agent-discovery-report.md)。

已有飞书工具会自动识别。新用户先按官方说明安装并用自己的账号授权；若要将工具装在当前用户目录，可执行：

```bash
npm install --global --prefix "$HOME/.local" @larksuite/cli
export PATH="$HOME/.local/bin:$PATH"
lark-cli --version
```

本机看板会识别常见的用户安装目录、Homebrew 和 nvm 环境；在其他目录安装工具时，先让命令在终端可用，再运行一次 Skill Pilot 安装命令，桌面入口会记住这些工具位置。SP 更新飞书时将新版放在当前用户的 `~/.local` 中，并优先使用；更新前备份，可撤销。

## 更新程序

打开看板时会自动检查一次；有新版时，技能页左边会出现提醒，设置里的“版本”也会直接出现“一键升级”，不用再点“检查更新”。

在看板打开 **设置 → 版本**：

1. 想立刻再查一次时，点“检查更新”。SP 从官方 GitHub 项目准备并检查新版。
2. 有新版时点“一键升级”。当前操作会先完成，桌面应用和命令行入口一起更新。
3. 出现“刷新生效”后点击它，或直接刷新浏览器，继续在原地址使用。

通过源码和 ZIP 安装的用户都可使用，不需要再找 agent 操作。启动检查和手动检查时联网；技能、分配、账号设置和密钥保留在用户自己的目录。下载或新版检查失败时继续使用原版；安装途中失败会自动恢复。程序文件有本地改动，或新版与其他文件重名时，会保留现有文件并说明原因。

**旧版首次接入这项功能**：先获取包含看板自助更新的新版文件，在项目文件夹运行一次 `sh scripts/build-app.sh`，再刷新看板。不支持刷新切换的更早版本，需要正常关闭全部看板页面后重开一次。完成后，后续普通升级直接在看板操作。

曾通过 ZIP 安装首版一键升级功能、检查时反复提示同一新版的用户，也需先按下面的手动更新步骤获取修复版并运行一次安装命令，重建程序文件清单。之后即可继续在看板升级。

也可以手动更新。在原项目文件夹获取新版文件：

```bash
git pull --ff-only
```

使用源码 ZIP 的用户，将新版解压到新的项目文件夹，再运行 `sh scripts/build-app.sh`，并正常关闭旧看板后打开新位置的应用。同一项目位置手动更新后，重新运行安装命令、刷新浏览器即可应用新版；当前操作会先完成，原地址和检查结果保留。

项目文件夹移动后，仍需在新位置重新运行安装命令。若新版提高 Python 等运行要求，且这台电脑尚未满足，SP 会保留原版并提示查看安装要求。

检查或下载新版时，连接暂时中断或超时会自动重试一次；权限不足和安全连接验证失败会直接说明原因。失败详情保存在当前用户的 `~/.skill-pilot/logs/program-update.jsonl`，包含时间、失败步骤、退出状态和经过清理的错误输出。打开看板时的自动检查失败也会记录；账号设置不参与记录，只读模式不写日志。

## 怎么用

- **打开看板**：双击 `~/Applications/Skill Pilot.app`（或 Spotlight 搜 “Skill Pilot”）。关掉页面 30 秒后程序自动退出。
- **升级 SP 自身**：设置 → 版本里点“检查更新 → 一键升级 → 刷新生效”；正在执行的操作会先完成，原地址和已检查的结果保留。
- **在对话里用**：首次整理后，打开看板会给已接入的 agent 安装 `skill-pilot` 技能，可以直接说“看看 Claude 有哪些技能”“把 X 也给 Antigravity”。
- **命令行**：`skill-pilot status`、`skill-pilot list --agent claude`、`skill-pilot check-updates`、`skill-pilot cleanup --list`，加 `--json` 输出结构化结果。

看板里的主要操作：

| 页面 | 做什么 |
| --- | --- |
| 技能 | 选择给哪个 agent 加上或撤下技能，依赖的技能自动一起带上，核对后应用 |
| 技能 → 首次整理 | 第一次使用时，把各 agent 现在用的技能收进一份技能库（先备份，可还原） |
| 技能 → 检查更新 | 按一下才查；可单独更新或全部更新；失败项列出原因，其他项继续；飞书技能整组更新 |
| 清理 | 手动选择不需要的技能，从各 agent 撤下（文件保留） |
| 清理 → 已撤下的技能 | 恢复撤下后没在用的技能 |
| 设置 → AI 整理 | 填 AI 服务，让技能有中文名、中文说明和分组 |
| 设置 → agent | 重新扫描 agent、接入新 agent、不再管理；其他技能文件夹也在这里记 |
| 设置 → 分享配置 | 导出在用技能、来源和分配；收到配置后先预览，再批量导入，可整批撤销 |
| 设置 → 操作记录 | 默认收起，展开看最近 10 次改动并撤销；完整记录可导出 |
| 设置 → 诊断与备份 | 排查版本差异、看各目录清单、整理与还原 |
| 设置 → 版本 | 从官方 GitHub 项目检查并升级 SP，更新启动入口，刷新后生效 |

分享给另一位 Skill Pilot 用户的方法见 [分享技能配置](docs/sharing-config.md)。配置不包含技能正文和账号密钥；自制或修改过的技能会列为待补齐。

团队里想互相看看在用什么技能：管理员在局域网电脑或 NAS 上运行团队分享站，同事在「设置 → 团队分享」连上后，就能在「团队」页分享自己的技能名单、挑同事的技能装上。部署和用法见 [团队分享站](docs/team-hub.md)。

新装了 agent，不用重启看板：在 **设置 → agent** 点 **重新扫描 agent**。打开看板时会先显示已保存的名单，再检查应用和常见技能目录；按钮会进一步查找主目录隐藏文件夹中的技能目录，显示扫描状态和上次检查时间。发现结果会保留到下次打开，接入、忽略和技能分配仍由你决定。为了快速显示名单，发现阶段不再统计每个候选 agent 的技能数，点击接入后在后台读取。详细技能盘点在打开“诊断与备份”或使用原来的盘点操作时读取。技能页底部先显示名单读取时间，打开诊断后改为盘点时间。

技能页和设置里的已发现 agent 都只需点一次「接入」，后台读取并显示进度；等待期间可以继续浏览技能，失败后可重试，完成后可撤销。同名技能沿用统一仓库里的版本；只有尚未收录、又存在多份不同内容的技能需要选一次版本。手动填写名字和文件夹时仍先显示预览。

## 数据放在哪

- 技能正本：`~/.skill-pilot/store/<技能名>/`（git 仓库）。各 agent 技能目录里只是指向它的链接，改技能直接改正本。
- 登记表、基准、操作记录、备份及显示设置：当前用户 `~/.skill-pilot/` 下的 `registry.json`、`bases/`、`logs/`、`backups/`、`labels.json`、`tags.json`（用户标签，与 AI 整理分开保存）。其他技能文件夹记在同一目录的 `extra-sources.json`。账号设置和密钥只保存在用户自己的 `settings.json` 中，不随项目或分享配置导出。
- 管理规则（给所有 agent 看）：[AGENTS.md](AGENTS.md)。

每次改动成功后，自动只保留最近 10 次还能撤销的操作备份；一次「全部更新」整批算一次，整批一起保留、一起清理。已经撤销的操作和撤销本身不再保留备份，更早的操作不能再撤销，完整操作记录仍可导出。升级后第一次改动会按同样规则清理旧备份，只读预览不清理。

首次整理前（包括还原后重新整理前）的备份一直保留，「设置 → 诊断与备份 → 整理与还原」和 `backups` 命令只列出这类备份，可以还原到整理前。操作失败且自动恢复也失败的备份一直保留；收编时挪开的原件也原样保留。

## 开发

先读 [AGENTS.md](AGENTS.md) 和 [docs/STATUS.md](docs/STATUS.md)。需求与决策历史见 [PLAN.md](PLAN.md)。

看板首页的动效用到 GSAP，文件和许可说明在 [skill_pilot/web/static/vendor/](skill_pilot/web/static/vendor/README.md)。

开发最高准则是 [通用化与可复现](AGENTS.md#最高准则通用化与可复现)。下面以满足上述版本要求的 `python3.11` 为例，测试只在系统临时目录中的模拟用户环境运行。

```bash
PYTHONDONTWRITEBYTECODE=1 python3.11 -m unittest discover -q
SKILL_PILOT_READ_ONLY=1 python3.11 -m skill_pilot status
sh scripts/build-app.sh   # 重新生成启动器和命令行入口
```
